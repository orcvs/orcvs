# The Language Map records spellings, not Atom types

The Language Map derives a row-local partition of Language Units from the character Source and then parses each Expression extent. Only one of those stages describes what the Source contains. The partition reads a two-Cell spelling and names it: a Bang, an Activation, a Function, or an operand literal. The parse resolves what a Function does with the operands it is given. A unit's kind records the spelling and nothing else, and parsing never writes back into it.

A literal keeps a single kind whichever Function consumes it. ADR 0021 holds that the same two characters spell a Number in a Number slot and a Note in a Note slot, and that Source stores literal characters rather than persistent type provenance. An `OperandLiteral` that became `Atom(Number(1))` because the Expression it sat in that Tick required a Number would be exactly that provenance, recorded in the one place the language says does not carry it. The consuming Function's signature answers the question at the point it is asked; `ExpressionEntry::atoms()` already carries the parsed values for the Expression that asked it.

The refinement this replaces could not have served a reader that needed it. It ran only for an executable extent, so a result written back into the Source — a bare literal standing alone, which is what a Portal read of a previous result finds — was never refined and stayed an operand literal regardless. A reader distinguishing a Number from a Note, such as the Increment and Interpolation Portal reads of ADR 0012, must therefore resolve the type from its own signature. That is the same answer ADR 0021 already gives, and it does not depend on what the partition stored.

Removing the refinement removes the reconciliation it required. `LanguageUnitKind` no longer carries an `Atom` variant. `LanguageMap::units` is the single owner of every unit: nothing overwrites a kind after the partition establishes it, so no pass exists to carry a second description home, and an Expression entry naming its units cannot disagree with the collection it names them in.

Two supports remain worth stating because later work will lean on them. The partition establishes units in row-major order — rows top to bottom, columns left to right within a row — so units ascend strictly by anchor index and an Expression extent names a contiguous run of them. That ordering is load-bearing wherever a run is located by search rather than by scan, so it is asserted where it is established rather than assumed where it is used. And the index spaces this derivation threads are distinct types: a Cell index addresses the Source and the Grid-sized Glyph collection, a unit index addresses the partition, both are machine words computed within a few lines of each other, and exchanging them type-checks while reading entirely the wrong data. `CellIndex` names the first and is mintable only by the Grid that contains it.
