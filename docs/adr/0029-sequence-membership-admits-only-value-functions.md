# Sequence membership admits only Functions that answer a value

ADR 0028 states that an instruction answers either a value or an effect, never both and never neither, and ADR 0004 states that Source-writing and external-output Functions are root-only and produce effects rather than values. Sequence membership follows from those two decisions rather than from a list of spellings: a Sequence is the value that carries results, so it admits an Atom holding a Function only when that Function answers a value, and refuses every Function that answers an effect. The Directional Bang Functions `*^`, `*v`, `*<`, and `*>`, the Halt Function `*!`, the Jump Functions `&^`, `&v`, `&<`, and `&>`, and the Terminal Output Functions are all refused by that one rule, and each effect Function added later joins them by its own definition rather than by an amendment here. ADR 0025 makes `Sequence::new` the single point at which membership is decided, so the rule is stated there and nowhere else and every Sequence Function inherits it with one diagnostic.

The check asks a Function's declared kind, not its spelling, and ADR 0024 records that spelling does not decide what an Atom is; an enumerated check naming `*^`, `*v`, `*<`, `*>`, and `*!` would be a third place to keep in step with the Function definitions, and it would silently admit the next effect Function added. The predicate is whether a Function answers a value, and that is not `Function::is_terminal`: `is_terminal` asks whether a Function performs a Terminal Output effect, and the two coincide today only because Terminal is the one effect kind `FunctionKind` defines. `FunctionKind` must therefore come to distinguish value from effect rather than value from Terminal Output, so that membership, the Interpreter's nesting guard, and tick planning's activation gate each ask the question it means of one declaration instead of borrowing a narrower one.

A Directional Bang Function is not a variant of the Self-Banging Function it emits, and the two are not excluded for the same reason at the same place. `*^` is an ordinary root Expression, inert until Bang activation like every other Function, whose effect is to write `^^` into the Source; ADR 0006 makes the Self-Banging Function the one explicit exception to that activation rule. Both are refused membership because neither answers a value, but by different mechanisms: `^^`, `vv`, `<<`, and `>>` are their own Atom variant, so refusing them stays one arm of a match the compiler makes exhaustive, while `*^` is an ordinary Function Atom refused by its kind. Naming the two groups together would obscure the activation asymmetry that is the reason both forms exist. This confirms ADR 0025's reading that membership is a role the Sequence defines over Atoms rather than a capability an Atom carries.
