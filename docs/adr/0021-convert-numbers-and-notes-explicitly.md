# Convert Numbers and Notes explicitly

Every literal occurrence identifies exactly one Atom type after its containing Expression is parsed against the consuming Function's fixed signature. The same two Source characters may therefore denote different Atom types in different typed operand positions: `C4` is Number `C4` where a Function requires a Number and Note `C4` where a Function requires a Note. Source stores literal characters rather than persistent type provenance; a standalone operand literal without typed Expression context is invalid. Orcvs does not globally coerce between Number and Note or let a Note operand change another Function's arithmetic domain.

The target numeric `.` family contains the paired conversion Functions `.v value` and `.^ value`. Their Source literal signatures are monomorphic: `.v Note` returns the Note's underlying MIDI Number, while `.^ Number` returns the corresponding Note for `00` through `7F` and diagnoses `80` through `FF`. Evaluation remains idempotent for composition: `.v` leaves an already-typed Number value unchanged, and `.^` leaves an already-typed Note value unchanged. These identity cases apply to values supplied by nested evaluation or Sequence broadcasting, not to the Function's literal operand slot. The conversions extend atom-wise across Sequences; if any element cannot convert, the complete conversion diagnoses and returns no partial Sequence.

The family prefix supplies the semantic namespace, so the directional suffixes do not claim a global meaning. Within `.`, `v` lowers a pitched value to its underlying Number and `^` raises a Number to a pitched Note. Other families may reuse those glyphs for spatial or future musical behavior without ambiguity. Notes retain their contextual two-Cell pitch spelling from `C/` through `G9`; the conversion Function's monomorphic literal signature distinguishes an overlapping hexadecimal spelling from a Note spelling just as every other typed Function signature does. Thus `.vA0` consumes Note `A0`, while `.^A0` consumes Number `A0` and diagnoses it as outside the MIDI range.
