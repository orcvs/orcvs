# Use distinct raw and timed Play Functions

Orcvs provides Raw Play as `!> channel velocity note` and Timed Play as `!~ channel velocity note length`. Both are terminal Functions activated by a Bang landing on their root, including a Bang sent by a Directional Bang Function. Separate names keep each prefix Function's arity fixed and explicit rather than making length optional or overloading one spelling. Raw Play leaves Note Off under explicit Source control through velocity `00`; Timed Play places its complete lifetime in the Tick Plan so the Playback Engine can schedule the corresponding Note Off without inferring musical intent.

For Raw, Timed, and Monophonic Play, channel is a Number in `00`–`0F`, velocity is a Number in `00`–`7F`, and note is a Note. Timed and Monophonic length is a Number in `00`–`FF`. Missing, mistyped, or out-of-range operands diagnose and emit no MIDI output. A caller with a MIDI Number uses the explicit `.^` conversion; Play does not infer a Note. These Functions send direct MIDI values without Orca's base-36 scaling or clamping.

A Timed command always requires and validates its length Number, including when velocity is `00`. After all operands validate, velocity `00` explicitly stops the specified note in Tick Plan order and schedules no expiry; the valid length value does not alter that stop behavior. With nonzero velocity, length `00` is a no-op: it emits no MIDI output, a note with zero lifetime never starts, and it leaves any prior Timed-owned note and its scheduled expiry untouched — unlike velocity `00`, it is not a stop command. A nonzero-velocity command produced at Tick `T` with positive length `N` starts in its Tick Plan order and schedules Note Off at the beginning of executed Tick `T + N`, before that Tick's new Play Commands, stopping the prior Timed-owned instance and invalidating its scheduled expiry before starting the replacement. Raw notes do not enter Timed ownership.

The MIDI subset of the Terminal Output family also includes Monophonic Play `!%`, Control Change `!c`, and Pitch Bend `!b`. Every MIDI terminal Function accepts direct hexadecimal MIDI data, validates protocol ranges, and never applies Orca's base-36 scaling, wrapping, or clamping.

Control Change has the fixed contract `!c channel controller value`. All three operands are Numbers. Channel accepts `00`–`0F`; controller and value accept `00`–`7F`. Pitch Bend has the fixed contract `!b channel lsb msb`. All three operands are Numbers. Channel accepts `00`–`0F`; LSB and MSB each accept `00`–`7F`, exposing MIDI's wire bytes directly.

Monophonic Play has the fixed contract `!% channel velocity note length`, matching Timed Play's operand shape. The Playback Engine owns at most one Mono voice per MIDI channel, in the same schedule that holds its Timed claims. This decision first gave that voice and its expiry to the selected output adapter, and that is corrected here rather than left standing: an Output Command is one message carrying no lifetime, so an adapter has nothing to schedule with, and giving it one would put musical time on the far side of the seam ADR 0001 draws. What the two owning spellings share is the schedule, the generation token, and everything that clears them; what they differ in is the key, which is Timed Play's channel and note against Monophonic Play's channel alone, and that key is the whole of the difference between polyphony and monophony here. Every Monophonic command first sends Note Off for the prior Mono-owned note on that channel, whatever note that was, since the voice is the channel and the Source need not remember what it last put there. Velocity `00` or length `00` then starts nothing, replacing the owned voice with silence. That parts from Timed Play, whose length `00` is a no-op, and the two are consistent rather than merely different: a Timed command claims the note it names, so a note that never starts claims nothing, while a Monophonic command claims its channel whether or not it sounds. Otherwise it sends Note On for the replacement and schedules its Note Off at executed Tick `T + length`. Each ownership change receives a generation token; replacement invalidates the prior token so a stale expiry cannot stop the new note. Different channels are independent; Raw Play and Timed Play notes do not enter Mono ownership, and Mono notes do not enter Timed ownership. Multiple commands retain Tick Plan order, with the last command owning the channel. Playback stop, adapter disconnect, destination change, and teardown after a refused delivery each send the safety action and clear Timed and Mono ownership. This decision first named that action all-notes-off, and that is widened here rather than left standing: `!c` and `!b` are the first spellings that set device state outliving the note that carried it, so CC 123 alone leaves a latched pedal down and a wheel deflected on a device Orcvs can no longer reach. The action is CC 123 All Notes Off, then CC 121 Reset All Controllers, then an explicit centred bend `[0xE0 | channel, 0x00, 0x40]`, on each of the sixteen channels in turn. CC 121 is the message the protocol provides for a sequencer stopping mid-gesture; the explicit centre is sent as well because device support for CC 121 varies and `0x2000` is unambiguous where that coverage is not, and it comes last so that a device which does honour CC 121 cannot move the wheel after it. Orcvs sends no explicit Note Off for the notes it knows it started, which is where it parts from Orca: All Notes Off is the message the protocol provides for silencing a channel, and a device that ignores it would equally ignore the CC 121 beside it. The schedule is discarded rather than played out, so the safety action is one fixed run of messages that does not vary with what happened to be sounding. OSC and UDP output remain deferred until Orcvs has message and text-like values rather than encoding them as exceptional raw Source reads.
