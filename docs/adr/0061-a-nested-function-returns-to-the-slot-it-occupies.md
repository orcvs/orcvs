# A nested Function returns to the slot it occupies

Status: accepted. Amends the nested-result clauses of [ADR 0034](0034-execute-against-live-typed-expressions.md). Not yet implemented; tracked in `.scratch/cell-tracker/issues/01`.

**A Function reads through input portals.** Its inline input portals are its operands, claimed greedily in signature order exactly as [ADR 0033](0033-partition-a-row-by-parse.md) already claims them: each portal sits at the next unclaimed Cell of the Expression, and if a Function spelling begins there that Function claims its own operands in turn before the next portal is placed. Its fixed input portals sit at a declared offset from its anchor, as Increment's and Interpolation's feedback Cell and each Jump's input do. Nothing about the parse changes. A portal's position is a fact of the current Source, and one coordinate system serves every read and write.

**A nested Function hands its answer to the inline input portal it stands in, as its two-Cell encoding.** That hand-off is the Return. The receiving portal decodes the Return by its declared literal type, exactly as it decodes characters a Portal wrote there, so a Note `C5` returned into an Addition operand is the Number `C5`. This replaces ADR 0034's typed nested result, under which the same Note stayed a Note and was refused. Nesting and spatial composition now deliver a value one way, which is what makes an inline nested Function shorthand for placing that Function where its output lands in the slot: `.+.+010102` behaves as if the inner Addition's `02` had been written into the outer one's first operand. Mixing Notes and Numbers stays explicit through the conversion Functions.

**A nested Function still writes through its own Output Portal.** The Return is an additional delivery, not a redirection. Every Function writes what it writes as a root would, and when it is nested the enclosing portal also receives that encoding. The reason is state. Increment and Interpolation keep their previous value in the Cell their Output Portal writes, because [ADR 0003](0003-source-snapshot-is-complete-language-state.md) leaves no other place for it. A rule that diverted a nested answer away from that Cell would leave a nested Increment reading an empty Cell, and answering the same value, every Tick. That is what the implementation does now: `PortalAccess::resolve` gives a nested Function no Output Portal, although ADR 0034 said a Function "can have both" a nested result and a spatial output. Writing south also makes the row below a nested Expression a visible trace of every step. In `.x.+.+01010203` the row below reads `0C0402`, each answer under the anchor that produced it.

**A nested Function that answers a Bang writes `**` and activates aligned roots**, under [ADR 0006](0006-bang-activation-includes-self-banging-functions.md), as a root does. Its Return is the Bang's encoding.

**A Function that cannot produce a two-Cell Return cannot nest, and the Parser refuses it.** An effect Function answers no value, and a Function that writes a List ([ADR 0063](0063-a-list-is-cells-in-a-claim-not-a-value.md)) answers more than one item. Both facts are declared by the Function, so the Language Map marks the refusal from any Source revision, and Source Paint shows it while the Source is being typed. Today the same refusal is diagnosed only during a Tick, as `NestedEffectFunction`.

## Consequences

The Cells south of a nested anchor are now written. A layout that puts an Expression directly under a nested Function loses it, as a layout under a root already does. Three tests in `orcvs/src/source/tick.rs` (`nested_computation_returns_and_projects_once`, `live_child_write_survives_parent_failure_…` and `a_value_replaces_nested_computation_…`) assert the opposite and change with this decision. A nested computation reserves its Output Portal's Cells, so the Language Map's rule that a nested Function is never covered by a Reservation ([ADR 0036](0036-reserve-result-cells-before-their-width-exists.md)) changes with it.

## Considered options

A Return that suppressed the nested Function's own write keeps the row below free, but needs a named exception for every Function whose Output Portal is also its input. A Return written over the nested Function's own anchor in Source erases the Function after one Tick. Applied only to a view of the Expression, it needs a second coordinate system for that view, beside the Grid's.
