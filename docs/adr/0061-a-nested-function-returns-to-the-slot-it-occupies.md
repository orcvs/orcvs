# A nested Function returns to the slot it occupies

Status: accepted. Amends the nested-result clauses of [ADR 0034](0034-execute-against-live-typed-expressions.md) and supersedes ADR 0060's typed nested-input wording while preserving its supplier ordering and placement rules. Amends the conversion pass-through clause of [ADR 0021](0021-convert-numbers-and-notes-explicitly.md), the "sole type-directed exception" of [ADR 0023](0023-use-distinct-range-functions-and-two-cell-comments.md) and the conversion identity exception recorded by [ADR 0028](0028-specify-the-orcvs-evaluation-machine.md): a Return carries no Atom type into `.v` or `.^`. Its Return for a blank operand is defined by [ADR 0062](0062-a-blank-operand-gives-a-blank-answer.md). Not yet implemented; tracked in `.scratch/cell-tracker/issues/02`.

**A Function reads through input portals.** Its inline input portals are its operands, claimed greedily in signature order exactly as [ADR 0033](0033-partition-a-row-by-parse.md) already claims them: each portal sits at the next unclaimed Cell of the Expression, and if a Function spelling begins there that Function claims its own operands in turn before the next portal is placed. Its fixed input portals sit at a declared offset from its anchor, as Increment's and Interpolation's feedback Cell and each Jump's input do. Nothing about operand placement changes. A portal's position is a fact of the current Source, and one coordinate system serves every read and write.

**A nested Function hands its answer to the inline input portal it stands in, as its two-Cell encoding.** That hand-off is the Return. The receiving portal decodes the Return by its declared literal type, exactly as it decodes characters a Portal wrote there, so a Note `C5` returned into an Addition operand is the Number `C5`. This replaces ADR 0034's typed nested result, under which the same Note stayed a Note and was refused. Nesting and spatial composition now deliver Source encoding one way, which is what makes an inline nested Function shorthand for placing that Function where its output lands in the slot: `.+.+010102` behaves as if the inner Addition's `02` had been written into the outer one's first operand. A Return loses the child's Atom type even when the receiver is `.v` or `.^`: `.+.^3C01` reads the returned `C4` as Number `C4`; `.v.vC4` diagnoses because the inner conversion returns `3C`, which is not a Note spelling; and `.^.^3C` diagnoses because the inner Return `C4` is read as Number `C4`, outside the Note range. Conversion remains an explicit operation on the Note or Number the receiver decodes; it is not preservation of the child's type.

**A nested Function still writes through its own Output Portal.** The Return is an additional delivery, not a redirection. Every Function writes what it writes as a root would, and when it is nested the enclosing portal also receives that encoding. The reason is state. Increment and Interpolation keep their previous value in the Cell their Output Portal writes, because [ADR 0003](0003-source-snapshot-is-complete-language-state.md) leaves no other place for it. A rule that diverted a nested answer away from that Cell would leave a nested Increment reading an empty Cell, and answering the same value, every Tick. That is what the implementation does now: `PortalAccess::resolve` gives a nested Function no Output Portal, although ADR 0034 said a Function "can have both" a nested result and a spatial output. Writing south also makes the row below a nested Expression a visible trace of every step. In `.x.+.+01010203` the row below reads `0C0402`, each answer under the anchor that produced it.

**A nested Function that answers a Bang writes `**` and activates aligned roots**, under [ADR 0006](0006-bang-activation-includes-self-banging-functions.md), as a root does. Its Return is the Bang's encoding.

**A Function that cannot produce a two-Cell Return cannot nest, and the Parser refuses it.** An effect Function answers no value, and a Function that writes a List ([ADR 0063](0063-a-list-is-cells-in-a-claim-not-a-value.md)) answers more than one item. Both facts are declared by the Function, so the Language Map marks the refusal from any Source revision, and Source Paint shows it while the Source is being typed. Today the same refusal is diagnosed only during a Tick, as `NestedEffectFunction`.

## Consequences

The Cells south of a nested anchor are now written. A layout that puts an Expression directly under a nested Function loses it, as a layout under a root already does. Tests that assert a nested Function leaves its south Cells alone change with this decision. A nested computation reserves its Output Portal's Cells, so the Language Map's rule that a nested Function is never covered by a Reservation ([ADR 0036](0036-reserve-result-cells-before-their-width-exists.md)) changes with it. A conversion nested in one of the same direction, `.v.vC4` or `.^.^3C`, now diagnoses where it used to pass the value through, and `.+.^3C01` adds Number `C4` without a diagnostic, so a performer who mixes Notes and Numbers through nesting gets the receiver's reading rather than the child's type.

## Considered options

A Return that suppressed the nested Function's own write keeps the row below free, but needs a named exception for every Function whose Output Portal is also its input. A Return written over the nested Function's own anchor in Source erases the Function after one Tick. Applied only to a view of the Expression, it needs a second coordinate system for that view, beside the Grid's.
