# A committed Tick records its Portal accesses

Status: accepted. Leaves [ADR 0009](0009-portals-resolve-tick-plan-destinations.md)'s rule that a Portal is internal Tick state, never a language value or persistent state, unchanged: what survives the Tick is a record of what its Turns did, not a Portal. Settled in `.scratch/tick-portals/`.

Orca lights each operator's ports as it runs, so its tracker shows a read head moving down each voice's column. Orcvs resolves a dynamic Input Portal at the Turn and drops it, so nothing outside the Tick knows which Cells a Function read. The console can paint only what a Render Frame can derive, and a Source revision alone does not say which Cells the Tick before it read. The Tick has to say.

## Decision

**A Tick plans its Tick Portals with its Tick Plan.** Tick Portals is an immutable, ordered list of Portal accesses, one entry per access, each carrying the Tick it observed. Execution is its only writer, and recording is unconditional: there is no generic recorder, no observer a caller installs, and no switch that turns recording off, so the record a test reads is the record Playback commits. The Tick Plan and the Playback Engine are unchanged; the record travels beside the plan, not in it.

**Each entry names its owner as execution held it.** The owner is the anchor of the Function whose Turn made the access, the Cells that Function's subtree holds — its spelling, every operand, and every nested Function's, from its anchor to the end of its last operand — and the Function that Turn executed, after any Function Replacement the Tick made before it. All three are captured during execution from the schedule's computation and the Turn's running Function, never recovered from the committed Source, which the Tick may have rewritten. An operand follows its Function in the row, so a subtree is one contiguous run of Cells, and another entry of the same record was made by one of the owner's descendants exactly when its anchor lies in those Cells and is not the owner's.

**A read is recorded once the Turn passes the writer wait.** It is the Input Portal the Interpreter is handed, with its origin — `Declared` where the Function declares the Portal at a fixed offset, `Selected` where its operands chose it this Turn — and its site. The site is the Input Span it resolved inside the Grid, as many Cells as the Turn reads, or the Portal Error that says why none resolved. A resolved site says a site was read, not that it held a value: whether the operand bound is the Turn's diagnostic, not the record's. A Turn that waits for a writer records nothing until it is retaken, so a retried Turn leaves exactly one read. A Turn the schedule refuses before interpretation — syntax, arity, suppression, an operand that does not decode, a Rest — records nothing, and its diagnostic stands as before.

**A write is recorded for each site delivery is asked to deliver to.** Declared or Selected as a read is, it is either the Output Span the Portal admitted or the Write Refusal that refused it whole: a geometric Portal Error, with the Position the write was attempted from where one exists inside the Grid; a Function Replacement that would change a fact the schedule was ordered by; or an ordering defect. The admitted write is recorded before any Contact it makes replaces a Function, so its owner is the Function whose Turn made it. A destination that resolved for a Turn whose interpretation then failed was never delivered to, and is absent.

**A lock and each Source Bundle part are recorded where execution decides them.** A Halt's lock carries the site it declares, or the Portal Error that puts the site outside the Grid, and the verdict the Tick gave it: the root it locked, the root it missed, an ordering defect, a site no Expression root holds, or nothing to lock. A Source Bundle records its parts as they run: `Vacate` for the producer's own Span a move clears, `Place` for the displaced destination, `LeftBang` for the `**` a refused move leaves, and `Fire` for the Span a Bang Function clears. A refused destination keeps why: the Portal Error, with the Position it was attempted from where one exists, or the Cells it needed when they were not vacant.

**Order is execution's.** Turns appear in the order they settled, and within a Turn its read comes first, then its writes in site order, its lock, or its Source Bundle parts in the order they ran.

**An Input Span is minted only from the Input Portal a Turn resolved, and an Output Span only from a write a Portal admitted.** Their constructors are private to Tick execution and each exposes only a read-only Span, so no Span from anywhere else can stand for a read or a write, and neither converts into the other.

**The record is committed through the one commit path.** The optimistic attempt carries the record in its planned Tick, and the locked attempt plans it under the guard; both hand the same Source commit one executed Tick, which only execution builds and which holds the plan with the record its Turns made, so no record can be committed beside a plan it does not observe. The commit stores the record with the revision it leaves. A refused attempt is dropped whole and publishes neither. Every committed Tick replaces the record, so a Tick that accessed no Portal leaves an empty record rather than the last one.

**A Source revision answers the last record with its freshness.** The Source keeps the last committed record with the revision that commit left and the set of Cells an edit has written since, and a revision captures all three as it is read, so an older revision keeps the record, and the edits, it was read with. The record is `Current` for the revision the commit left, and `Retained` for a revision an edit has made since. A retained record's Positions still name the Cells the Tick accessed, because an edit never moves a Cell, but the Function that made an entry may no longer stand at its anchor. Stopping Playback changes no revision, so a paused tracker keeps its record. Opening or loading a Source builds a new Source, which has none until its first Tick, and the record is not persisted.

**The Render Frame paints resolved reads as Input Portal, admitted writes as Output Portal, and locked roots as Locked.** Derivation sets the Input Portal role on each Cell a resolved read covers, the Output Portal role on each Cell an admitted write covers, declared or selected, and the Locked role on the two Cells of the Function of each Expression root a lock withheld, in place over the Cells it has built, so a record costs no allocation per frame. Orca draws the Cells an operator locks in a style of their own; the Cells a Halt locks are the root's own spelling, which is where the root it withholds stands, so a locked `**` shows as plainly as a locked Add. The static Output Portal highlight paints beside them, so a Function whose Turn wrote nothing still shows its own. A read whose site did not resolve, a refused write, a lock that withheld no root (missed, refused for an ordering defect, aimed at no root, or with nothing to lock) and every Source Bundle part stay in the record and paint nothing.

**A Cell's roles combine, and the console paints one of them.** A Cell can play any set of the three roles. The console paints Output Portal over Input Portal over Locked: a Cell a Function both reads and writes shows the write, and a locked Cell a Function reads or writes paints as that read or write would, as Orca draws a port over a locked Cell. Output and Input Portal leave a bound Function's own paint alone; Locked paints it, and a Bang, because those are the only Cells a lock marks. A locked Function's spelling that a Function also reads or writes therefore keeps its own paint and shows no lock: the Portal wins, and a Function keeps its paint inside a Portal.

**A retained record paints only the entries whose place no edit has changed, directly or through a nested read.** A `Current` record paints every resolved read and admitted write. A `Retained` record paints a read or a write only where the displayed revision's Language Map claims the entry's anchor for a Function that begins there and parsed as the entry's Function, the way a schedule anchors a computation, and no edit since the commit has written a Cell of the owner's subtree as the entry recorded it. The Function and every operand Cell stand inside that subtree, so a subtree no edit has touched spells what it spelled then; an edit to it — `&v01` to `&v02`, or a new Function at the anchor — puts out its entries until the next Tick. An edit elsewhere in the Expression leaves them lit: rewriting `.+&v01&v02`'s Add as a Subtract moves neither Read, and overwriting the outer Read of `&v&v01` leaves the inner Read standing on unedited Cells, reading where it read. A `Selected` read or write also needs every resolved read the record holds from a strict descendant of its owner to have read no Cell an edit has written since, because such a read answers one of the owner's operands with Cells outside the subtree: in `&v&v01` the outer Read selects its Cells by what the inner Read reads. A `Declared` entry's place is a fixed offset from its anchor, so a nested read cannot move it. A Halt's lock site is a fixed offset too, so no nested read can move a lock: it stays marked while the Halt stands at its anchor, no edit has written the Halt's own Cells, and no edit has written the Cells the mark lands on, the locked root's own spelling. Overwriting that spelling leaves no Function to mark, so it puts the lock out until the next Tick; an edit to the locked root's operands leaves the mark standing, as editing what a Read reads leaves that Read lit. Every Source Bundle site is a fixed offset as well, and a Source Bundle part paints nothing. The descendant is found by the Cells each entry's owner's subtree holds, so a chain of nested Reads puts out each Read the edited Cell feeds, through a Function between them that made no access of its own, and a sibling Read in the same Expression is not put out. Editing what a Read reads leaves that Read's own entries lit. The record's own reads say which Cells each nested read resolved, so nothing beyond the record and the edited Cells is kept. Writing back what stood there is still an edit and does not light them again: the rule asks whether the subtree was edited, not what it holds. Editing one voice of a paused tracker therefore leaves the other voices' reads and writes lit. The record itself is unchanged by an edit; only its paint is derived again.

The edited Cells are one bit per Cell, 8 KiB on the shipped 256 × 256 Grid, marked by every write but a Tick commit's and cleared by each commit, which reuses their storage. A revision shares them as it shares the Cells, so marking copies them only while a revision still holds them, which is when the edit copies the Cells too; marking a Cell already marked writes nothing.

## Consequences

- The console lights each `&v` read of the tracker as it steps, with the Input Portal role ADR 0009's static Output Portal highlight sits beside, and lights where each selected write (Write, Push, `=$`) landed.
- The console marks the root each Halt locked in the last Tick with the Locked role's Theme channels, `locked.*`, until an edit reaches the Halt or the locked root's spelling, or the next Tick commits.
- `TickPortals`, `PortalUse`, `PortalEvent`, `PortalOrigin`, `InputSpan`, `OutputSpan`, `WriteRefusal`, `LockVerdict`, `BundlePart`, `BundleRefusal`, `PortalError`, `Freshness` and `RevisionTickPortals` join the public surface of the `orcvs` crate, which no one outside this workspace consumes.
- Every Tick allocates its record once, reserving room for one access per computation in its schedule, and its handle when it commits. A Tick with no computation reserves no entries. The per-Tick cost is inside the `source_execute_tick*` benchmarks, which plan and commit Ticks that read and write.

## Considered options

- **A recorder the caller installs.** Execution would call out to an observer at each access. It splits the record a test reads from the one Playback commits, and a shipped seam a caller can leave empty is a branch only a test needs.
- **Folding the record into the Tick Plan.** The Tick Plan is what the Playback Engine applies; the record is what the console observes. Keeping them apart leaves the engine's input unchanged.
- **Testing the edited Cells over the Expression that covers the anchor in the displayed revision.** It puts out every entry of an Expression for an edit that moves none of them, such as rewriting the Add of `.+&v01&v02`, and it needs a Language Map lookup per entry; the subtree the entry recorded answers the same question from the record.
- **Comparing an owner's Expression with the Cells the commit left.** It would light an entry again when an edit writes back what stood there, which nothing asks for, and keeping the commit's Cells shares the Source's copy-on-write buffer, so the first edit after every Tick would copy every Cell.
- **Putting out every entry anchored after an edited read in its Expression.** It needs nothing beyond the Expression, but a Read beside the edited one in the same Expression, and a Function whose place is declared, would go out though the edit cannot move them.
- **Recording each entry's parent anchor.** Descent would follow parent links from each edited read, but a Function between them that made no access leaves no entry to carry its own parent, so each entry would need its whole chain of ancestors. The subtree's Cells answer the same question with one Span.
- **Validating a retained entry by its anchor and Function alone.** An operand edit leaves the Function standing, so a dynamic read would stay lit on Cells the edited Function no longer reads until the next Tick.
- **Dropping the record at the first edit.** A revision an edit made would answer no record, so no read could paint against Cells it was not committed with. Every keystroke into a paused tracker would then put out every voice's read, not only the one the edit changed.
- **Marking the whole subtree a lock withheld.** The lock withholds every Turn of the locked Expression, but the record names only the root's anchor, and the root's operands are what its own Turn would have read; marking them would compete with the Portal roles a read of those Cells sets. The root's spelling is what Orca's one locked Cell is.
- **Dimming a locked glyph, as Orca does.** Orcvs Light's Function, Number and Note glyphs already stand at the contrast floor on their own tints, so a dimmer glyph falls below it. The built-ins wash a locked Cell toward the Source background and frame it instead, and a Theme can still set `locked.foreground`.
- **Deriving the paint from the committed Source.** A Tick may rewrite the Cells its owners stood in, and a dynamic read's site depends on operands the Tick itself wrote. Only execution knows which Cells were read.
