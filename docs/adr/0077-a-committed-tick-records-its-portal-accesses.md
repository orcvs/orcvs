# A committed Tick records its Portal accesses

Status: accepted. Leaves [ADR 0009](0009-portals-resolve-tick-plan-destinations.md)'s rule that a Portal is internal Tick state, never a language value or persistent state, unchanged: what survives the Tick is a record of what its Turns did, not a Portal. Settled in `.scratch/tick-portals/`.

Orca lights each operator's ports as it runs, so its tracker shows a read head moving down each voice's column. Orcvs resolves a dynamic Input Portal at the Turn and drops it, so nothing outside the Tick knows which Cells a Function read. The console can paint only what a Render Frame can derive, and a Source revision alone does not say which Cells the Tick before it read. The Tick has to say.

## Decision

**A Tick plans its Tick Portals with its Tick Plan.** Tick Portals is an immutable, ordered list of Portal accesses, one entry per access, each carrying the Tick it observed. Execution is its only writer, and recording is unconditional: there is no generic recorder, no observer a caller installs, and no switch that turns recording off, so the record a test reads is the record Playback commits. The Tick Plan and the Playback Engine are unchanged; the record travels beside the plan, not in it.

**Each entry names its owner as execution held it.** The owner is the anchor of the Function whose Turn made the access and the Function that Turn executed, after any Function Replacement the Tick made before it. Both are captured during execution from the schedule's computation and the Turn's running Function, never recovered from the committed Source, which the Tick may have rewritten.

**A read is recorded once the Turn passes the writer wait.** It is the Input Portal the Interpreter is handed, with its origin — `Declared` where the Function declares the Portal at a fixed offset, `Selected` where its operands chose it this Turn — and its site. The site is the Input Span it resolved inside the Grid, as many Cells as the Turn reads, or the Portal Error that says why none resolved. A resolved site says a site was read, not that it held a value: whether the operand bound is the Turn's diagnostic, not the record's. A Turn that waits for a writer records nothing until it is retaken, so a retried Turn leaves exactly one read. A Turn the schedule refuses before interpretation — syntax, arity, suppression, an operand that does not decode, a Rest — records nothing, and its diagnostic stands as before.

**A write is recorded for each site delivery is asked to deliver to.** Declared or Selected as a read is, it is either the Output Span the Portal admitted or the Write Refusal that refused it whole: a geometric Portal Error, with the Position the write was attempted from where one exists inside the Grid; a Function Replacement that would change a fact the schedule was ordered by; or an ordering defect. The admitted write is recorded before any Contact it makes replaces a Function, so its owner is the Function whose Turn made it. A destination that resolved for a Turn whose interpretation then failed was never delivered to, and is absent.

**A lock and each Source Bundle part are recorded where execution decides them.** A Halt's lock carries the site it declares, or the Portal Error that puts the site outside the Grid, and the verdict the Tick gave it: the root it locked, the root it missed, an ordering defect, a site no Expression root holds, or nothing to lock. A Source Bundle records its parts as they run: `Vacate` for the producer's own Span a move clears, `Place` for the displaced destination, `LeftBang` for the `**` a refused move leaves, and `Fire` for the Span a Bang Function clears. A refused destination keeps why: the Portal Error, with the Position it was attempted from where one exists, or the Cells it needed when they were not vacant.

**Order is execution's.** Turns appear in the order they settled, and within a Turn its read comes first, then its writes in site order, its lock, or its Source Bundle parts in the order they ran.

**An Input Span is minted only from the Input Portal a Turn resolved, and an Output Span only from a write a Portal admitted.** Their constructors are private to Tick execution and each exposes only a read-only Span, so no Span from anywhere else can stand for a read or a write, and neither converts into the other.

**The record is committed through the one commit path.** The optimistic attempt carries the record in its planned Tick, and the locked attempt plans it under the guard; both hand the same Source commit one executed Tick, which only execution builds and which holds the plan with the record its Turns made, so no record can be committed beside a plan it does not observe. The commit stores the record with the revision it leaves. A refused attempt is dropped whole and publishes neither. Every committed Tick replaces the record, so a Tick that accessed no Portal leaves an empty record rather than the last one.

**A Source revision answers the last record with its freshness.** The Source keeps the last committed record with the revision that commit left, and a revision captures it as it is read, so an older revision keeps the record it was read with. The record is `Current` for the revision the commit left, and `Retained` for a revision an edit has made since. A retained record's Positions still name the Cells the Tick accessed, because an edit never moves a Cell, but the Function that made an entry may no longer stand at its anchor. Stopping Playback changes no revision, so a paused tracker keeps its record. Opening or loading a Source builds a new Source, which has none until its first Tick, and the record is not persisted.

**The Render Frame paints resolved reads as Input Portal and admitted writes as Output Portal.** Derivation sets the Input Portal role on each Cell a resolved read covers and the Output Portal role on each Cell an admitted write covers, declared or selected, in place over the Cells it has built, so a record costs no allocation per frame. The static Output Portal highlight paints beside them, so a Function whose Turn wrote nothing still shows its own. A read whose site did not resolve, a refused write, every lock and every Source Bundle part stay in the record and paint nothing.

**Diagnostic paints over Input Portal, and Output Portal over Diagnostic.** A resolved read covers every Cell the Turn read, whatever stood there, so a read can land on another Expression's Invalid operand. The read says the Cells were read, not that they bound, so it does not hide the diagnostic that says why they did not: such a Cell paints its Diagnostic as if no Portal covered it. A write landing there is the Tick changing those Cells, so Output Portal paints over the Diagnostic as it does for the static highlight. The contrast and colour-vision matrices still measure every Portal role set; the Cells this changes paint a Diagnostic state they already measure.

**A retained record paints only the entries whose owner still stands.** A `Current` record paints every resolved read and admitted write. A `Retained` record paints a read or a write only where the displayed revision's Language Map claims the entry's anchor for a Function that begins there and parsed as the entry's Function, the way a schedule anchors a computation. Editing one voice of a paused tracker therefore leaves the other voices' reads and writes lit, and a Function the edit changed stops claiming accesses it no longer makes.

## Consequences

- The console lights each `&v` read of the tracker as it steps, with the Input Portal role ADR 0009's static Output Portal highlight sits beside, and lights where each selected write (Write, Push, `=$`) landed.
- `TickPortals`, `PortalUse`, `PortalEvent`, `PortalOrigin`, `InputSpan`, `OutputSpan`, `WriteRefusal`, `LockVerdict`, `BundlePart`, `BundleRefusal`, `PortalError`, `Freshness` and `RevisionTickPortals` join the public surface of the `orcvs` crate, which no one outside this workspace consumes.
- Every Tick allocates its record once, reserving room for one access per computation in its schedule, and its handle when it commits. A Tick with no computation reserves no entries. The per-Tick cost is inside the `source_execute_tick*` benchmarks, which plan and commit Ticks that read and write.

## Considered options

- **A recorder the caller installs.** Execution would call out to an observer at each access. It splits the record a test reads from the one Playback commits, and a shipped seam a caller can leave empty is a branch only a test needs.
- **Folding the record into the Tick Plan.** The Tick Plan is what the Playback Engine applies; the record is what the console observes. Keeping them apart leaves the engine's input unchanged.
- **Dropping the record at the first edit.** A revision an edit made would answer no record, so no read could paint against Cells it was not committed with. Every keystroke into a paused tracker would then put out every voice's read, not only the one the edit changed.
- **Deriving the paint from the committed Source.** A Tick may rewrite the Cells its owners stood in, and a dynamic read's site depends on operands the Tick itself wrote. Only execution knows which Cells were read.
