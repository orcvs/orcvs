# Track reads a Portal as Jump does

Status: accepted. Supersedes the List clauses of [ADR 0063](0063-a-list-is-cells-in-a-claim-not-a-value.md): Orcvs has no List claim, no literal count read when the Source is parsed, and no untyped Item. ADR 0063's removal of the Sequence value and the `:` family stands. Amends [ADR 0032](0032-schedule-tick-execution-by-dependency.md): a dependency can be found at a Function's Turn. [ADR 0070](0070-read-write-and-copy-are-separate-families.md) moves Track to `&t` and renames Jump to Copy; the first 2026-10-10 amendment below extends the wording to every dynamic Input Portal, and the second orders every dynamic Output Portal and amends ADR 0034's ordering-bug clause for dynamic writes.

**Track is an ordinary value Function with an Input Portal: `@t index count`.** `index` and `count` are Number operands like any other. Either can be a literal, a nested Function or Cells a Portal writes, and an empty one makes Track invalid ([ADR 0069](0069-an-unwritten-operand-is-invalid-input.md)). At its Turn Track reads the two Cells `index % count` pairs east of its last operand, so `@t0103C4D4E4` reads `D4`. It answers what it reads through its Output Portal and, nested, as its Return. A `count` of `00` is diagnosed at the Turn, as a wrap by zero is for every other Function. A pair past the row edge is diagnosed, as a Jump's Input Portal outside the Grid is.

**Track reads its Input Portal exactly as a Jump does ([ADR 0014](0014-spatial-functions-preserve-performative-behaviour.md)).** Empty Cells are copied: Track clears its Output Portal and, nested, returns them, so its parent is invalid (ADR 0069). `**` answers a Bang, which Track relays through its Output Portal and which activates a root there. A Function spelling answers that Function, so Function Replacement applies where it lands. A Number or a Note answers that Atom. Anything else, such as a partial pair, a Comment or Cells that straddle two Language Units, is diagnosed as partial or invalid input. Track has no reading rules of its own.

**The Cells east of Track are ordinary Source.** Track claims only its operands. The Cells it selects from are parsed, painted and edited as any other Source, and the pair Track reads is whatever working Source holds there at its Turn. Whether a bare value such as `C4` standing on its own is diagnosed is a question for the Parser. It applies equally to Cells a Jump reads, so this decision does not answer it.

**Track's read is ordered by ADR 0032's rule, completed at Track's Turn.** A Function goes after whatever writes the Cells it reads. A Jump's Input Portal is a fixed offset from its anchor, so its dependency is known before the Tick. Track's pair depends on `index` and `count`, which are themselves inputs, ordered before Track by the same rule. Once they settle, Track's pair is known. Any writer of that pair that has not yet taken its Turn goes first, and Track takes its Turn after it. If that writer waits on Track, the two form a same-Tick dependency cycle, diagnosed under [ADR 0065](0065-an-error-never-stops-the-performance.md). The loop that orders Turns continues during the Tick so that a dependency found at a Turn can join it. Nothing is reserved for Track before the Tick, and every other Function is ordered as before.

## Amendment: static and dynamic Input Portals

An Input Portal is named by when its position is known. A static Input Portal's position is a fixed offset from its Function's anchor, known when the Source is parsed: a Jump's Input Portal is static, as are Increment's and Interpolation's, so its dependency is known before the Tick. A dynamic Input Portal's position is selected by its Function's operands, by a rule each such Function's definition states, so its dependency is found at its Turn. Track's Input Portal is dynamic. The distinction is of position, not contents: every Input Portal's Cells are read from working Source at its Function's Turn.

## Considered options

- **A List in Track's claim (ADR 0063).** Track's Items were part of its Expression, its count was a literal fixed when the Source was parsed, and its Items were copied untyped. Track then needed its own parse, its own Language Unit kind, its own answer and its own copy rules, none of which Jump needs. Rejected for a Function that reads Cells and answers them.
- **Ordering Track after every writer east of it to the row edge.** This needs nothing from `count`, but it orders writers Track never reads and can report a cycle that does not exist.
- **Ordering Track after writers in the `count` pairs the Source holds when the Tick starts.** This freezes the count for the Tick and fails when the count is nested.
- **Not ordering Track's read, as Orca's `T` does.** Track would read whatever its turn in Grid order finds, so a writer east of it or below it would be seen a Tick late.

## Consequences

A cycle found at Track's Turn preserves completed Turns and stops the remaining
computations in every Expression it reaches, per [ADR 0068](0068-a-discovered-cycle-preserves-completed-turns.md).

When `index` and `count` are literals that nothing writes during the Tick, Track's pair is known before the Tick. Its dependency could then join the schedule built in advance, which keeps that schedule reusable across Ticks. This is an optional optimisation that never changes what Track reads. Add it only when a benchmark shows the Turn-time path costs something.

A Track that reads `**` activates the root its Output Portal lands on, as a Jump does. This differs from ADR 0063, where a copied `**` was characters and activated nothing.

## Amendment, 2026-10-10: every dynamic Input Portal

[ADR 0070](0070-read-write-and-copy-are-separate-families.md) renames Jump to Copy and moves Track from `@t` to `&t`; where this decision says Jump it means the Copy Function, and `@t index count` is `&t index count`. `@t` is now Push. What this decision states for Track holds for every Function with a dynamic Input Portal: each directional Read `&^ &v &< &> n`, the absolute Read `&$ column row` and the read of the absolute Copy `=$`. Each reads its Input Portal exactly as a Copy does and has no reading rules of its own, the Cells it reads are ordinary Source, and its read is ordered by ADR 0032's rule completed at its Turn: once its operands settle, every writer of the pair it reads that has not taken its Turn goes first, and a writer that waits on it forms a cycle under ADRs 0065 and 0068. Each Function's definition states how its operands select its pair. Track counts its list in pairs from the end of its last operand; a directional Read counts Portals from the slot its `n` operand occupies; an absolute Read addresses a Position.

## Amendment, 2026-10-10: dynamic Output Portals

An Output Portal is static or dynamic by when its position is known, as an Input Portal is. A static Output Portal is a fixed offset from its Function's anchor: one row south by default, or the side a directional Copy's arrow names. A dynamic Output Portal is the pair its Function's operands select, known only at its Turn. Each directional Write `@^ @v @< @> n value`, the absolute Write `@$ column row value`, Push `@t index count value` and the write of the absolute Copy `=$` have a dynamic Output Portal; the directional Copies keep static ones.

**A Write answers `value` through its dynamic Output Portal and nowhere else.** South is only the default Output Portal, and a Write names the pair its operands select instead, so it writes one row south only when that pair is the one selected, as Push's lane pair `00` is ([ADR 0070](0070-read-write-and-copy-are-separate-families.md)'s amendment on Push's lane). Nested, a Write returns `value` to the slot it occupies and still writes through its Output Portal, as every nested Function does under [ADR 0061](0061-a-nested-function-returns-to-the-slot-it-occupies.md), so `@$0000@$0101C4` writes `C4` at both Positions. A destination outside the Grid or cut short by the row edge rejects the write and keeps the answer for a parent's Return, per [ADR 0034](0034-execute-against-live-typed-expressions.md). `=$` answers the pair it copies in the same way.

**A dynamic writer takes its Turn as early as its inputs allow.** No reader can wait on a dynamic writer's destination, because the destination exists only at the writer's Turn. Instead the schedule orders the dynamic writers among themselves by what feeds them, Grid position breaking ties, and orders each one before every computation that neither feeds it nor feeds a dynamic writer ordered before it. Static readers, dynamic readers and nested readers in another Expression all come after it and see its write in the same Tick, including a reader north or west of it. A computation that feeds the writer comes first: its operands and nested children, and anything the writer finds it must wait for at its Turn, such as a static writer of the pair a `=$` reads. That found dependency overrides the writers-first ordering: the computation the writer waits for goes first, and the writer goes after it.

**A write onto Cells a completed Turn has already read is feedback, seen on the next Tick.** No Turn is reordered once taken and none is taken twice. The Write that steps itself, `@x 00 value`, is one case. A counter such as `@$0602.+&$060201`, whose nested Read is upstream of the Write and reads `05` before the Write puts `06` there, is another: it advances one step per Tick. A Source that reads a Cell by Position before or after a write within the Tick does so by its own design.

**Independent dynamic writers are ordered by Grid position,** as ADR 0034 breaks every other tie. The earlier writer goes first, and a nested writer goes before the writer it feeds. A later writer's write onto the earlier one's operands, or onto anything that fed it, is feedback, and the later write wins a pair both reach. A static writer that does not feed a dynamic writer comes after it, so the static write wins a pair both reach. A dynamic write onto a Function's spelling suppresses or replaces that Function in this Tick if its Turn is still to come, and from the next Tick if it has been taken. This is the exception to ADR 0034's rule that an overwrite reaching an already-attempted computation is an ordering bug: for a dynamic write it is feedback.

**A transient effect that reaches a Turn already taken is missed, and diagnosed as missed.** A Bang's activation and a Halt's lock last only for the Tick that produces them ([ADR 0032](0032-schedule-tick-execution-by-dependency.md)), so neither can be carried to the next Tick as feedback. When a dynamic write's Bang reaches a root that has already taken its Turn, or a Halt that joined the Tick through such a Bang locks a computation that has already taken its Turn, that activation or lock is lost for this Tick and diagnosed at its target as missed. It is not a cycle: nothing is stopped, and every other effect of the Turn still applies, including the `**` display and the activation of other roots that have not taken their Turn. The rule is the same whether the target fed the writer itself or fed an earlier dynamic writer that Grid position put first.

**A dynamic writer forms a diagnosed cycle only through dependencies it actually has.** A writers-first ordering never closes a cycle, because the ordering gives way when the writer finds a dependency at its Turn. A cycle through a real dependency, such as a `=$` nested in a value Function whose south Output Portal covers the pair the `=$` reads, is diagnosed under [ADR 0065](0065-an-error-never-stops-the-performance.md) and [ADR 0068](0068-a-discovered-cycle-preserves-completed-turns.md), as the same shape with a nested Read already is. A `=$` whose source and destination overlap is one Turn that reads and then writes. A Function never waits on its own write, so no cycle forms. Overlapping the same pair rewrites it unchanged. Overlapping by one Cell shifts what it copies one Cell along. Where that leaves Cells that, on the next Tick, straddle two Language Units, as a copied Function spelling does, the `=$` diagnoses them as partial input under the Copy reading rules; where the Cells it reads still form one unit, such as a Number in an operand slot, it copies again.

**Schedule reuse is unchanged.** Which computations are dynamic writers, and what feeds each one statically, are scheduling inputs, so the writers-first ordering belongs to the schedule shared across Ticks. Where a write lands, and an ordering a found dependency overrides, belong to one Tick and never change the schedule. A write onto an operand leaves the scheduling inputs as they were. A write onto a Function's spelling changes them, so the next revision is scheduled afresh.

### Considered options

- **Leaving dynamic writers where dependencies and Grid position put them, as Orca does.** A writer south or east of its reader would be seen a Tick late, which this decision already rejected for Track's read. It would keep ADR 0032's same-Tick promise for every Function except the Writes.
- **Re-taking a reader's Turn after a later write reaches its Cells.** A Producer takes at most one Turn, and a write that feeds its own input, such as the counter, would never settle within the Tick.
- **Ordering a dynamic writer before everything outside its static inputs, with no exception for a dependency found at its Turn.** It reports cycles for writes that never land on the Cells in question, the flaw that rejected ordering Track after every writer east of it.
- **Diagnosing a write onto already-read Cells as a cycle.** It would forbid counters, generators and the Write that steps itself.
- **Diagnosing two dynamic writes that reach the same pair.** ADR 0034 composes competing writes deterministically; rejecting only dynamic ones would put a second rule beside it.
- **A Write that also answers one row south.** It doubles every Write's output, clutters the Grid under it and reserves Cells there for nothing.
- **A Write whose write is a Source effect with no answer.** A nested Write would supply nothing and its parent would be invalid under [ADR 0069](0069-an-unwritten-operand-is-invalid-input.md), so Writes would not compose.
- **Silently losing a Bang or lock that reaches a Turn already taken,** as Orca drops a missed bang. The performer could not tell why a root never fires, and it would repeat every Tick.
- **Diagnosing such a missed Bang or lock as a cycle.** Nothing is stopped, and when the target fed only an earlier dynamic writer the cause is Grid order, not a dependency the writer has.
- **Diagnosing a `=$` whose source and destination overlap as a cycle.** It is one Turn, and a Function never waits on its own write.
- **Never reusing a schedule while a dynamic writer exists.** The writers-first ordering is structural, so every Tick would pay a full reschedule for nothing.
- **Reserving a Write's destination before the Tick when its address operands are literals nothing writes.** Unlike the optimisation this decision allows for Track, it changes behaviour: a reader that feeds the Write would wait on its reservation and form a cycle where this decision gives feedback.
