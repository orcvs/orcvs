# Exclude Activation Functions from Sequence membership

Sequence membership excludes the five Activation Functions `*^`, `*v`, `*<`, `*>`, and `*!` for the reason that already excludes the four Self-Banging Functions `^^`, `vv`, `<<`, and `>>`: each is a root-only Source effect rather than a value. A Directional Bang emits a Self-Banging Function and Halt locks the Expression root directly south; neither answers with a language value, so neither is an operand, a result, or a member of the value that carries results. ADR 0025 makes `Sequence::new` the single point at which membership is decided, and this exclusion is stated there and nowhere else, so every Sequence Function inherits it with one diagnostic rather than restating it.

The two exclusions share a reason but not a shape, which is why the rule cannot be left to the existing check. A Self-Banging Function is its own Atom, so refusing it is one arm of a match the compiler makes exhaustive. An Activation Function is an ordinary Function Atom, indistinguishable at that level from a Function that does answer with a value, so the wildcard that admits the Function family today would admit each Activation Function by default as it is added. The membership check must therefore name the five Functions, and the `*` prefix they happen to share is not what names them: spelling does not decide what an Atom is, as ADR 0024 records. This confirms ADR 0025's reading that membership is a role the Sequence defines over Atoms rather than a capability an Atom carries — the deferred `Member` type would name three refusals, not two.
