# A List is Cells in a claim, not a value

Status: accepted. Supersedes [ADR 0007](0007-sequence-is-a-first-class-value.md), [ADR 0025](0025-check-sequence-membership-at-one-construction-point.md), [ADR 0026](0026-consider-modelling-every-value-as-a-sequence.md), [ADR 0029](0029-sequence-membership-admits-only-value-functions.md), [ADR 0030](0030-terminal-output-functions-extend-over-sequences.md) and [ADR 0039](0039-pulse-functions-refuse-a-sequence-operand.md); the Sequence clauses of [ADR 0009](0009-portals-resolve-tick-plan-destinations.md), [ADR 0017](0017-sequences-and-portals-replace-cell-batch-operators.md), [ADR 0020](0020-order-tick-effects-by-source-position.md), [ADR 0021](0021-convert-numbers-and-notes-explicitly.md) and [ADR 0036](0036-reserve-result-cells-before-their-width-exists.md); the Range Function decisions of [ADR 0023](0023-use-distinct-range-functions-and-two-cell-comments.md); the Atom-or-Sequence value model [ADR 0028](0028-specify-the-orcvs-evaluation-machine.md) assumes; the `:` family of [ADR 0008](0008-preserve-symbolic-arithmetic-functions.md) and [ADR 0035](0035-spell-the-comment-as-a-parser-unit.md); the Sequence mappings of [ADR 0019](0019-map-orca-capabilities-onto-orcvs-language-families.md); and the broadcasting clauses of ADRs 0011 to 0013. The Sequence value, its Functions, pervasive extension and variable-width Reservations are retired (`.scratch/cell-tracker/issues/01`), and Track is implemented (`.scratch/cell-tracker/issues/04`).

**Orcvs has no Sequence value. A List is a horizontal series of two-Cell items inside one Function's claim, and its length is a literal count operand of that Function.** Each item is a two-Cell encoding or blank. A List is Source: it exists only as Cells, a performer edits it in place, and the Source File holds it. It is never a Return, never passes between Functions, and is typed only by the portal that receives one of its items.

A Sequence could reach a Function only as a nested result. ADR 0036 says so: a Sequence written to Source re-reads as separate Atoms, because [ADR 0007](0007-sequence-is-a-first-class-value.md) gives it no literal spelling. [ADR 0061](0061-a-nested-function-returns-to-the-slot-it-occupies.md) makes a Return exactly one two-Cell encoding, which leaves a Sequence no way to travel. The value also cost the language three things a List does not. A Sequence could not hold the Absence Marker ([ADR 0025](0025-check-sequence-membership-at-one-construction-point.md)), so it could not hold a rest, and the pulse Functions had to refuse it ([ADR 0039](0039-pulse-functions-refuse-a-sequence-operand.md)). Its width did not exist until it was evaluated, so ADR 0036 had to reserve every Cell a result could reach. And it was invisible: the pattern a performer wanted to edit existed only inside an evaluation.

**A List lives in the claim of the Function that reads it, directly east of that Function's operands.** The Parser owns the items, so they are parsed, painted and edited as part of that Expression and never by a second reader. The count is read when the Source is parsed. The count established by parsing governs the claim, modulo selection and zero validation for the whole Tick. A Portal write that changes the count changes all three from the next Tick, so [ADR 0032](0032-schedule-tick-execution-by-dependency.md)'s dependency graph stays fixed before execution. The schedule includes every Item in the established claim as a possible current-Tick read, and Track reads the selected Item's surviving working Source Cells after their suppliers settle. A List runs east within one row only, because a claim never crosses a row edge (ADR 0033). Lists at an address given by Position operands ([ADR 0049](0049-a-position-is-two-numbers.md)), and vertical Lists, are deferred: each brings back geometry the schedule cannot know in advance.

**Items are untyped.** A Function that reads an item copies its two characters, and the portal that receives them decodes them. A malformed Note in a List is therefore diagnosed where it is played, not where it is written, and one reader serves Notes, Numbers and any other encoding.

**Track is the first List Function: `@t index count`, followed by its List.** It answers the item at `index % count` every Tick, without Bang activation, as other value Functions do. Wrapping lets any index source drive a List of any length, as Orca's `T` does. A count of `00` diagnoses. A blank item is copied like any other ([ADR 0066](0066-an-unwritten-operand-leaves-its-function-pending.md)): Track writes the empty Cells through its Output Portal and, when nested, returns them, so the receiving operand is empty and its Function pending either way. Track answers one item, so it can nest: `!~0064@t0208C4D4E4  G4C5  E404` is a one-row tracker whose Play takes its note from a nested Track. `@t` follows the existing letter spellings such as Control Change `!c` and Pitch Bend `!b`; a general spelling sweep is outside this effort.

**The `:` family is retired. List Functions belong to `@`, the family that reads and writes Source.** The Sequence Functions Range, Reverse, Concatenate, Select and Replace are removed with the value. Each returns as a List Function only when a program needs it, since editing the Source directly does most of what they did. Pervasive extension is removed with them. A chord is several Play roots that one Bang activates, which needs nothing new, since a Bang activates every aligned root.

The Sequence entries in `CONTEXT.md` and the Function reference are retired when this decision is implemented, not before, because until then they describe the code.

## Frozen count, live Items

Implementing Track settled how the count and the Items meet one Tick's schedule.

**The count is frozen for the Tick; the Items are read live.** The Parser reads the count as a literal Number before any Function evaluates and records one Item per counted position. That claim decides the Tick's Items, the wrap and the zero check, and Track's Turn takes the count from the claim rather than from working Source, so a same-Tick write to the count Cells changes nothing until the next Tick parses them: with index `02`, a count grown from `02` to `03` still selects Item zero in the Tick of the write and the third Item in the next. Every Item of the claim is a current-Tick read in the dependency schedule, so a producer of any Item takes its Turn before Track whether it stands before or after it in Grid order, and a cycle through any Item read rejects the whole Tick. Track reads the index and the selected Item's characters from working Source at its Turn, after those producers settle, and never from the Snapshot: partial and competing writes compose Cell-wise in Turn order, and an absent or failed supplier leaves the surviving Cells.

**A count the Parser cannot establish claims nothing.** A Function spelling in the count slot is refused rather than nested, and so are a blank and a malformed count; the Cells after them are the next Expression's Source. A count of `00` is refused by the Parser. A count the row cannot hold still records every counted Item, the short and missing ones with the Cells the row left, and is refused, so no selection reaches Cells outside the claim. Track gives no answer in each case and the Expression's diagnostic says why.

**The claim is a scheduling input.** The Items the Parser records are compared like every other positioned entry when a revision decides whether to share a schedule, so a count edit orders a new schedule while an index or Item edit keeps it. Whether a Function reads a List is a fact a Function Replacement may not change, because the Items were claimed for the Function the Parser found.

**Items are Language Units of their own kind, and their characters are copied untyped.** A written Item is a Language Unit that records no Atom and never diagnoses where it stands; a blank Item is none, as a blank operand is none. Source Paint identifies each Item as Source in its Function's claim. Track copies the selected characters through its Output Portal and, nested, returns them; the receiving operand decodes them as it decodes any written Cells, so a malformed Item diagnoses at the operand that reads it. An empty Item is copied like any other, which the Absence Marker is not: an Expression answering the Absence Marker writes nothing and leaves the previous Note, where a copied empty Item clears it. Copied `**` is characters, so it activates no root in the Tick it is copied.
