# A List is Cells in a claim, not a value

Status: accepted. Supersedes [ADR 0007](0007-sequence-is-a-first-class-value.md), [ADR 0025](0025-check-sequence-membership-at-one-construction-point.md), [ADR 0026](0026-consider-modelling-every-value-as-a-sequence.md), [ADR 0029](0029-sequence-membership-admits-only-value-functions.md) and [ADR 0030](0030-terminal-output-functions-extend-over-sequences.md); the Sequence clauses of [ADR 0017](0017-sequences-and-portals-replace-cell-batch-operators.md), [ADR 0036](0036-reserve-result-cells-before-their-width-exists.md) and [ADR 0039](0039-pulse-functions-refuse-a-sequence-operand.md); and the broadcasting clauses of ADRs 0011 to 0013. Not yet implemented; tracked in `.scratch/cell-tracker/issues/03` and `04`.

**Orcvs has no Sequence value. A List is a horizontal series of two-Cell items inside one Function's claim, and its length is a literal count operand of that Function.** Each item is a two-Cell encoding or blank. A List is Source: it exists only as Cells, a performer edits it in place, and the Source File holds it. It is never a Return, never passes between Functions, and is typed only by the portal that receives one of its items.

A Sequence could reach a Function only as a nested result. ADR 0036 says so: a Sequence written to Source re-reads as separate Atoms, because [ADR 0007](0007-sequence-is-a-first-class-value.md) gives it no literal spelling. [ADR 0061](0061-a-nested-function-returns-to-the-slot-it-occupies.md) makes a Return exactly one two-Cell encoding, which leaves a Sequence no way to travel. The value also cost the language three things a List does not. A Sequence could not hold the Absence Marker ([ADR 0025](0025-check-sequence-membership-at-one-construction-point.md)), so it could not hold a rest, and the pulse Functions had to refuse it ([ADR 0039](0039-pulse-functions-refuse-a-sequence-operand.md)). Its width did not exist until it was evaluated, so ADR 0036 had to reserve every Cell a result could reach. And it was invisible: the pattern a performer wanted to edit existed only inside an evaluation.

**A List lives in the claim of the Function that reads it, directly east of that Function's operands.** The Parser owns the items, so they are parsed, painted and edited as part of that Expression and never by a second reader. The count is read when the Source is parsed. A Portal write that changes the count changes the claim from the next Tick, so [ADR 0032](0032-schedule-tick-execution-by-dependency.md)'s dependency graph stays fixed before execution. A List runs east within one row only, because a claim never crosses a row edge (ADR 0033). Lists at an address given by Position operands ([ADR 0049](0049-a-position-is-two-numbers.md)), and vertical Lists, are deferred: each brings back geometry the schedule cannot know in advance.

**Items are untyped.** A Function that reads an item copies its two characters, and the portal that receives them decodes them. A malformed Note in a List is therefore diagnosed where it is played, not where it is written, and one reader serves Notes, Numbers and any other encoding.

**Track is the first List Function: `@t index count`, followed by its List.** It answers the item at `index % count` every Tick, without Bang activation, as other value Functions do. Wrapping lets any index source drive a List of any length, as Orca's `T` does. A count of `00` diagnoses. A blank item is answered as a blank, which writes spaces south and makes a receiving operand blank under [ADR 0062](0062-a-blank-operand-has-no-effect.md). Track answers one item, so it can nest: `!~0064@t0208C4D4E4  G4C5  E404` is a one-row tracker whose Play takes its note from a nested Track. `@t` follows [ADR 0064](0064-a-function-spelling-starts-with-punctuation.md)'s spelling rule.

**The `:` family is retired. List Functions belong to `@`, the family that reads and writes Source.** The Sequence Functions Range, Reverse, Concatenate, Select and Replace are removed with the value. Each returns as a List Function only when a program needs it, since editing the Source directly does most of what they did. Pervasive extension is removed with them. A chord is several Play roots that one Bang activates, which needs nothing new, since a Bang activates every aligned root.

The Sequence entries in `CONTEXT.md` and the Function reference are retired when this decision is implemented, not before, because until then they describe the code.
