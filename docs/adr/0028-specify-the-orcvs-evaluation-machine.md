# Specify the Orcvs evaluation machine

Orcvs evaluates every Expression on a stack machine, and this decision names that machine and states what it guarantees. An Expression parses to a flat sequence of at most `EXP_LEN` Atoms in prefix order, where the root Function comes first and its operands follow. The Evaluator walks that sequence from last Atom to first. A literal Atom pushes one value onto the Operand Stack. A Function pops the operands its signature declares and pushes one value in their place. The right-to-left walk is not an implementation preference: it is what makes a Function's operands reach it in signature order, so reversing it would silently transpose every operand of every non-commutative Function.

The machine has no memory of its own. Its Operand Stack is created for one Expression and discarded when that Expression answers, so nothing carries from one Expression to the next or from one Tick to the next. ADR 0003 already makes the Source Snapshot the complete language state, and this decision keeps the Evaluator consistent with it: there are no registers, no heap, no persistent variables, and no program counter spanning Expressions. Orcvs is therefore not a virtual machine and should not be described as one. It has no bytecode, because the Atom sequence is re-derived from character Source on every Tick rather than compiled, and it has no control flow, because activation and Portals are Source-resident behaviour rather than machine instructions. The accurate term is a stack-based expression evaluator whose memory is the Source.

The instruction set is one specification, declared in one place. Most of it already is: `define_functions!` in `lang/src/atom.rs` is that one canonical table, and the `Function` enum, `ALL`, every spelling, every kind, every signature, and the parser's `TryFrom<&str>` are all generated from it, under a compile-time assertion on spelling width and a denied `unreachable_patterns` that turns two definitions sharing a spelling into a compile error. What is still restated outside that table is an operand's role and position, which live only in the body of the Function that reads it, as bare indices, so transposing Raw Play's channel and velocity compiles and evaluates without a diagnostic. Two extraction paths do exist where the language describes one rule with one exception, but that is the exception rather than drift: `.^` and `.v` take a numeric value at evaluation instead of the single type their signature declares, which is the idempotence for nested values that ADR 0021 requires. The parser's literal token list, the operand extraction, the evaluation dispatch, and each operand's role name are therefore derived from the single declaration rather than restated beside it. This decision fixes that the declaration is single and derived-from; it does not fix its form.

An instruction answers either a value or an effect, never both and never neither. A Terminal Output Function answers a Play Command and is valid only at the Expression root, as ADR 0016 requires, and the Evaluator never pushes an effect onto the Operand Stack. An Expression that leaves no value answers the absence marker, which is distinct from the empty Sequence that ADR 0007 defines as a value.

Every bound the machine relies on is either proven or diagnosed, and never assumed. The parser bounds an Expression at `EXP_LEN` Atoms and diagnoses a longer one. The Operand Stack has a separate bound that is neither derived from `EXP_LEN` nor checked: a 64-Cell Expression of 32 Atoms, which the parser accepts, overflows the 16-slot stack and panics inside the push. That panic unwinds rather than aborting. It leaves the Evaluator inside Tick planning, before any Cell of that Tick is committed, and passes back out through the Source write guard and the Playback lock, both of which recover from poisoning, into the clock task whose handle nothing holds. The process survives, the editor survives, and the Source stays consistent; what stops is Playback, silently and with no diagnostic, which makes the failure harder to trace than an abort rather than milder. That is a defect against this decision rather than a limitation of it. The Operand Stack must either be proven sufficient for every Expression the parser accepts, with its bound derived from `EXP_LEN` rather than written as a separate number, or it must answer a diagnostic when it is exhausted. A panic is not an acceptable third option, because the Evaluator runs inside a Tick, under the Source lock, while Playback continues.

Two questions this decision deliberately leaves open. The value model is still ADR 0007's Atom-or-Sequence pair, and ADR 0026 records the uniform alternative in which every value is a Sequence; that choice belongs to the value model rather than to the machine, and it changes how operands are described without changing anything above. The form of the single instruction-set declaration is likewise open: it may be types, or data, or a mixture, and this decision constrains only that there is one of it and that everything else is derived.
