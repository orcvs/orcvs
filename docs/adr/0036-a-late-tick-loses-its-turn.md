# A late Tick loses its turn

Every Tick of a Playback run is due at a whole multiple of the Tick period from the deadline that run began on, and that grid holds for the life of the run. A deadline the clock cannot reach in time is skipped: the Tick due at it is declined with one Overrun diagnostic naming the deadline it missed, the deadlines that passed unreached behind it are not manufactured so they can be declined in turn, and the run resumes at the next deadline still on the grid. This completes [ADR 0002](0002-playback-engine-owns-lifecycle-concurrency.md), which gave the Playback Engine its clock and said overruns become diagnostics without stopping later Ticks, but never said what a run owes the deadlines a stall covered.

**The grid is the thing a sequencer cannot give up.** Orcvs is played against a beat, and a Tick landing at a fixed multiple of the period from the moment the run began is the property a player would notice the absence of. The two rules this one rejects both surrender it or pay for it in Ticks nobody hears. Replaying the backlog holds the grid but delivers every missed deadline at once, and each arrives with an observed time past its own deadline plus a period, so `is_overrun` declines all of them: the catch-up is spent entirely on Ticks that produce a diagnostic and no sound. Restarting the period from the moment the clock woke costs nothing in Ticks but moves the grid, and the shift is permanent — the run plays out its remaining life offset by however long that one stall happened to last, and a second stall offsets it again.

**One Overrun means one stall.** Overrun counts a missed deadline, not a missed period, so a run that lost three seconds of a one-second grid reports once and names the deadline it was due at. This matters because it is the only signal a stall leaves: `shell/src/diagnostics.rs` maps Overrun to no user-facing message, so the count exists for tests and for whatever later reads it, and a count that scaled with the length of a stall would be reporting the clock's arithmetic rather than the event.

**The declining stays with the execution, not the clock.** `is_overrun` is what refuses a Tick whose observed time has already passed its deadline by a whole period, and it keeps that job under this decision. The clock answers when the next Tick is due; the engine answers whether the Tick it was handed is still worth executing. A Tick that is late but inside its own period is executed rather than declined, which is what makes an ordinary slow Tick cost nothing at all.

**Both targets hold this rule, and the tests hold them to each other.** Both clocks compute their next deadline with `next_scheduled_at`; the native clock waits with `tokio::time::sleep_until` and the browser clock uses its browser timer. Tokio's `MissedTickBehavior::Skip` applies only when lateness exceeds five milliseconds, so it cannot enforce this rule for the supported one-to-five-millisecond Tick periods. The parity test runs native start and retune through a missed deadline at short periods and at one second, asserting one Overrun and resumption at the shared rule's next deadline.

**The divergence this replaces was never decided.** The rule arrived as `Skip` in the commit that introduced overrun detection, became the backlog rule four hours later in a commit whose subject was moving the clock into the Playback Engine, and became the moving-grid rule on the browser two days after that in a commit whose subject was making playback run in a browser at all. Neither change mentioned a policy, because neither was about one. The backlog rule then acquired an end-to-end test asserting its consequence in the same commit that introduced it, which is why every run of CI since has agreed with it. Nothing here was reopened: this is the first time the question has been asked.

**Which is why it is written down.** A missed deadline had no name in `CONTEXT.md` and no ADR, and this repository gates the decisions it has named — an unnamed one survives a refactor, a port, a crate split, and an architecture review that reads the divergence as deliberate. The rule is stated here so the next clock has something to be wrong against.
