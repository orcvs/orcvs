# Evaluate turns against working Source

Status: superseded by [ADR 0032](0032-schedule-tick-execution-by-dependency.md). This records the historical row-major fallback, not the accepted execution contract. See [dependency-ordering research](../../.scratch/language-map/dependency-ordering-research.md) and [music/dataflow research](../../.scratch/language-map/music-dataflow-ordering-research.md).

The subsequent user-confirmed Bang rule supersedes this candidate's cleanup-turn and cross-Tick activation behavior: `**` is output display, manual `**` is a no-op, and only the current Tick's produced Bang activates. The current fallback implementation has not yet been updated to this rule. See [the executable ordering exploration](../../.scratch/language-map/operation-ordering-exploration.md).

When Functions write Note C4 into a MIDI Play Expression and Bang adjacent to its root before that root's turn during Tick T, C4 must play during T. Frozen operands and deferred read visibility fail this fundamental musical requirement. Keep one row-major turn order, as in Orca, but evaluate against working Source: validate a complete write before applying it, then make it visible to later turns immediately; commit the final Source atomically and hand the ordered Play Commands to Playback for the same Tick.

The starting Source Snapshot remains the complete persistent language state and determines candidate Function identities and parsed Bang cleanup turns. A Function already present at an Expression root can receive a candidate turn even when its operands are incomplete or invalid at Tick start: earlier writes may complete it. At its turn, parse the current Expression, check current activation where required, and evaluate its current operands, including nested Functions. Each original root receives at most one opportunity. A write touching its original Function Cells suppresses that old turn, even if the spelling is restored; newly generated Function code, including a newly generated nested Function, waits until the next Tick. Completing or changing ordinary operands does not generate a new Function.

Bang remains a value, not a standalone Function. Only contextually valid parsed Bang Atoms provide adjacency activation or cleanup; `**` rejected in a typed operand position does neither and retains its syntax diagnostic. A valid Bang in the starting Snapshot receives a cleanup turn at its own anchor in the same row-major order. That turn clears the complete original Bang Span only if current parsing still identifies the same Bang there and no preceding admitted write touched either Cell. A partial overwrite leaves the remaining fragment to ordinary syntax diagnostics; it is not partly cleared. Even a write of the same `**` replaces the old pulse, whose cleanup cannot erase the new pulse. Roots before its cleanup can observe it; roots after cleanup cannot. A generated Bang is immediately visible to subsequent roots but receives no cleanup turn until the next Tick. It can therefore be observed in its production Tick and again before cleanup in the next Tick; a pulse does not mean exactly one root activation.

A Portal may address a Cell above its producer. This does not rewind an earlier root: an upward write remains Source for the next Tick unless overwritten, but activation then still depends on the Bang remaining valid and visible when that root takes its turn. In particular, cleanup may precede a target next Tick. There is no guarantee that every Portal placement triggers every neighbor, and no dependency scheduler or repeated root evaluation. Evaluating all value roots before terminal roots would help backward MIDI delivery but would not solve backward dependencies between value roots and would introduce another ordering rule for Halt, Jump, and moving Functions; retain the ordered approach rather than introduce that partial solution.

This supersedes the fixed-Snapshot read and generated-Bang timing clauses in ADRs 0003, 0004, 0006, 0009, 0012, 0014, and 0020. Starting-Snapshot reproducibility, whole-write admission, producer/emission conflict order, generated-code deferral, and the Source/Playback separation in ADR 0001 remain. It does not change which Function families require activation: the implementation currently evaluates value-producing roots without a Bang, while ADR 0006's broader ordinary-root gating is separate work.
