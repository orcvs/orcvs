# Spell the Comment as a Parser unit

Status: accepted. Supersedes the Comment clause of [ADR 0023](0023-use-distinct-range-functions-and-two-cell-comments.md) and the Comment paragraph of [ADR 0033](0033-partition-a-row-by-parse.md); corrects the Comment row of [ADR 0019](0019-map-orca-capabilities-onto-orcvs-language-families.md). Every other decision in all three stands.

A Comment is a Language Unit the Parser establishes. It is spelled `||` and claims every remaining Cell of its row. This supersedes the Comment clause of [ADR 0023](0023-use-distinct-range-functions-and-two-cell-comments.md), which spelled it `##`, and replaces the Comment paragraph of [ADR 0033](0033-partition-a-row-by-parse.md), which held the rule as a byte pre-pass run ahead of the walk. One `|` alone is incomplete or invalid Source, exactly as one `#` was.

**The spelling moves off `#` because `#` belongs to the Note domain.** ADR 0023 gave `#` two jobs at once: `:#` names Note Range, and `##` opened a Comment. `#` is the notation the musical domain reaches for first, and holding it for the one construct that has no musical meaning spends the language's most idiomatic pitch character on its least musical unit. Freeing it leaves `:#` unambiguous and leaves `#` available as a sigil for a pitch family should one be declared.

**The doubled glyph is the operandless family.** Three sigils open Functions that take operands — `.` for Value, `!` for Terminal Output, `:` for Sequence — and each names a domain in its first Cell and an operation in its second. Beside them sit the units that take nothing: `**` Bang and the `^^ vv << >>` Activations, each a glyph repeated, and each a glyph whose single form is not a sigil. A Comment takes nothing, so it belongs there, and `||` is the member of that family that collides with no other reading: `|` is not a sigil and appears in exactly one spelling, `.|` Absolute Difference, as a second Cell. Two vertical rules divide a row, which is what a Comment does to one.

**`!!` and `//` were considered and refused.** `!!` would be the only doubled glyph whose single form is a sigil, so the `!` column would stop meaning "this row makes noise" in the one case where it means the row is inert — the inversion a Grid notation can least afford, because a Grid is read down its columns. It would also spend a slot from the family [ADR 0004](0004-source-functions-plan-spatial-effects.md) grows, whose Halt, Directional Bang, and Jump are themselves operandless. `//` was refused because `/` is the octave-zero marker in Note spelling as well as `./` Divide's second Cell, which makes it the most load-bearing punctuation in the very domain this decision protects.

**A Comment is a Cell claim, not an operand list.** The Parser already decides, for every unit, how far its claim reaches, and it already gives that question three answers: a Bang and an Activation claim their two Cells, and a Function claims two plus what its signature declares. A Comment is a fourth answer — claim the rest of the row — stated at the same point, and it needs no new mechanism to state it. It is not modelled as a Function with a row-length parameter list: operand counts are fixed per Function in the Function table, the inline operand storage of [ADR 0028](0028-specify-the-orcvs-evaluation-machine.md)'s Operand Stack is sized from that table at compile time, operands are typed as they bind, and a Function must answer a value or an effect. Comment text is arbitrary and is never decoded, typed, or evaluated, so it carries none of those. It is recorded with a Token and no Atom, which is also why it can carry text at all: an Atom is a fixed-width value and cannot hold a row.

**A Comment answers no value, performs no effect, and is never scheduled.** Both follow from the shape rather than from a rule added to enforce them. An Expression answers Atoms only when every entry carries one, and a Comment entry carries none. A root is the anchor of a leading Function, and a Comment's leading entry is not one, so no Turn is ever reserved for it. It needs no `FunctionKind` and no arm in the interpreter.

**`||` opens a Comment only where an Expression could start.** Inside a Function's arity-determined claim, `||` is an operand Cell of that Function, which fails to bind and diagnoses. This is the decided reading of ADR 0033's partition by parse: a Comment introducer is a spelling like any other, and a spelling is recognized only in the position where a spelling is read.

**The pre-pass was unsound, not merely misplaced.** `source_end` searched the row for `##` over every overlapping byte pair rather than stepping in two-Cell units, which was safe only while no Language Unit spelling held a `#`. ADR 0023's own `:#` made that false: an Expression may begin at any column, so `:#` followed by a `#` presented `##` at an offset the walk would cut the row at, in the middle of a Function, one keystroke into a Live Edit. Moving the rule into the parse removes the unaligned scan rather than repairing it, and the new spelling removes the collision class as well.
