# The console owns the Source Grid transform

Status: accepted. Settles how the presentation crate [ADR 0022](0022-keep-the-core-crate-free-of-the-ui-toolkit.md) carved out draws the Grid. It does not reopen [ADR 0005](0005-defer-source-addressing-for-infinite-canvas.md).

The console holds the scale and translation the Source Grid is presented under rather than handing them to an `egui::Scene`. It applies them itself when it computes each Cell's rectangle, and it derives the `FontId` size from the same scale, so a Glyph is laid out at the zoom it is drawn at instead of being scaled after the fact. `console/src/grid_viewport.rs` remains the single expression of the square-Cell fit and the letterboxing; what changes is that its numbers reach the painted rectangles directly instead of reaching them through a container's layer transform.

**What forces the choice is `Arc::make_mut`, three crates down.** `Scene::show` sets a layer transform on the layer it creates (`egui-0.36.1/src/containers/scene.rs:214`), and `GraphicLayers::drain` applies that transform to every shape in the layer at end of pass (`egui-0.36.1/src/layers.rs:213-256`). For a `TextShape` that is `TextShape::transform`, which reaches the galley through `Arc::make_mut` (`epaint-0.36.1/src/shapes/text_shape.rs:134`) and each of its rows through `Arc::make_mut` again (`:153`). `make_mut` clones only when the refcount is above one — and epaint's `GalleyCache` keeps an `Arc::clone` of every galley it hands out, on the cache-hit path and the cache-miss path alike (`epaint-0.36.1/src/text/fonts.rs:1055-1163`). The refcount is therefore never one, the clone is never elided, and it is a deep clone: the `Galley`, each `Arc<Row>`, and each row's tessellated vertex buffer. Under a transformed layer the Source Grid pays that once per Cell per Render Frame, on the main thread — a thousand times at the default Grid. No drawing change removes it, because a painter holding its own cached galley has exactly the same refcount and takes exactly the same clone. Only leaving the transformed layer removes it, which is why ownership of the transform, and not the drawing, is what this decision is about.

**Two further things follow from the same layer transform, and neither is about cost.** Glyph quads are scaled after rasterisation while sampling a fixed-resolution atlas, so text is bilinearly resampled rather than laid out at the zoom it is shown at — soft above zoom 1.0 and chunky below it. And `Glyph::pos` is deliberately left untransformed behind an acknowledged upstream `TODO(emilk)` (`text_shape.rs:150`), so glyph positions inside a transformed galley are stale and cannot be trusted for geometry. Deriving the `FontId` size from the owned scale removes the first; not transforming galleys at all removes the second.

**The cost is smaller than retiring a container sounds, and overstating it would be the easy mistake.** `Scene::register_pan_and_zoom` is public and takes a `&mut TSTransform` the caller owns (`scene.rs:229`). It applies the drag-pan for the configured buttons, the zoom-at-pointer transform, the `zoom_range` clamping and `Response::mark_changed`, and it does **not** set a layer transform — that is `Scene::show`'s separate call at `:214`. So this decision gives up no pan and zoom input handling; it gives up the layer transform alone, and the helper is kept and called with the console's own transform. What the console genuinely takes on is applying that transform when it computes Cell rectangles, rebuilding the fit rather than borrowing it (`fit_to_rect_in_scene` is a private `fn`, `scene.rs:15`, and `grid_viewport` already holds the numbers), guarding a degenerate transform where `Scene::show` used to reset one (`scene.rs:151-152, 168-173`), accounting for the `set_sublayer` and `force_set_min_rect` calls that leave with the container (`scene.rs:192-194, 220`), and replacing the helper's drag-pan branch, which multiplies by `to_global.scaling` (`scene.rs:239`) to undo a division `Response::drag_delta` only performs when a layer transform exists. The fit-to-viewport reset was already console code (`console/src/console.rs:365-367, 389-393`).

**The survey found no precedent, and that is a better argument than a precedent would have been.** No surveyed egui terminal renderer leaves the transformed layer. `peters/horizon` is on this exact pin, draws its grid with no per-cell widgets, and calls `ctx.set_transform_layer` as the first act of the areas that hold it (`app/panels.rs:604-614`, `app/view.rs:189-193`). It pays the galley clone unnoticed: its profiling spans cover shape building and `tessellate_shapes`, while the clone happens in `GraphicLayers::drain` inside `end_pass`, which no span covers. An unnoticed cost in a mature implementation is the reason to write the mechanism down rather than a reason to doubt it. The implementations that avoid the clone avoid it by never zooming through a transform at all.

**Laying out one Glyph per Cell is a deliberate divergence, not an unoptimised loop.** `horizon` coalesces contiguous same-foreground cells into one string and lays that run out as a single galley (`terminal_widget/render.rs:146-175`). With a ligature-bearing font, that shifts columns. epaint 0.36 shapes through harfrust and passes no feature list (`epaint-0.36.1/src/text/text_layout.rs:1433`), so the shaper's default horizontal features — `liga` and `calt` among them — apply; a ligated cluster emits one glyph plus zero-width continuations (`text_layout.rs:224-232`), and `extra_letter_spacing` is added only at cluster boundaries, never within one (`:282-297`). So `->`, `==` and `!=` consume two Cells as one form and move the rest of the row. This console's font has both features (`console/assets/MonaspaceNeon-Regular.otf` carries `liga` and `calt` in its `GSUB` table) and the Source's character set is dense in exactly those pairs. A Cell is the unit of layout because a Position must land where the Grid says it does; a later reader tempted to batch the per-Cell loop back into runs is reading a correctness constraint as a missed optimisation.

## Rejected alternatives

**Keep the `Scene` and emit glyph quads into a hand-built `Mesh`.** A mesh the console builds has a refcount of one, so nothing clones when the layer transform reaches it. The construction is available: copy the vertices of `RowVisuals::mesh` over the `glyph_vertex_range`, and normalise their UVs, which epaint documents as non-normalised texel coordinates that the caller must divide by the texture size (`epaint-0.36.1/src/text/text_layout_types.rs:852-870`), against `font_image_size()` (`fonts.rs:780`). It removes the clone. It does not remove the resampling, since the quads still sample a fixed-resolution atlas at a scale the layer applies afterwards. And it buys the clone's removal with a standing dependency on epaint's texel-space UV convention and on the exact layout of a public-but-internal vertex range, in a crate this repository pins rather than controls. No surveyed egui terminal renderer hand-builds a glyph mesh; every one goes through `Shape::text` or `Shape::galley`. Paying an upstream-coupling risk to keep a container that is the source of the other two problems is the wrong trade.

**Zoom the whole console with `ctx.set_zoom_factor`.** `zoom_factor` scales `pixels_per_point` directly (`egui-0.36.1/src/context.rs:2308-2345`), so text is laid out natively at every zoom. This is how `landaire/hxy` zooms. It is genuinely the cheapest answer to everything above: no transform to own, no `FontId` size to derive from a scale, no quantisation step to choose, no extra glyph sizes rasterised into the atlas, and no clone, because there is no layer transform anywhere. Its cost is that it zooms the console, not the Source Grid: the menu bar, the diagnostics and every control grow with the Cells. Zooming into a Source while the chrome stays put is the behaviour the console has today and the one being kept, so this is rejected for what it does to the rest of the window rather than for anything it does to the Grid.

## Consequences

Text sharpness at zoom visibly changes, and it is an improvement rather than a parity break: today's Glyphs are bilinearly resampled at any zoom away from 1.0, and under this decision they are laid out at the size they are drawn at. The effort's parity claim covers the palette and the geometry, not resampling artefacts, and a reviewer comparing captures will see the difference.

Deriving the `FontId` size from a continuous scale would rasterise a fresh glyph set per distinct size, and `subpixel_binning` — on by default (`epaint-0.36.1/src/text/mod.rs:62`) — multiplies that, so the scale reaching the `FontId` is quantised. The step is an atlas budget before it is a cache-hit rate: `Fonts::begin_pass` replaces the whole `FontsImpl` — a new atlas with empty glyph caches — whenever `TextOptions` change or `atlas.fill_ratio() > 0.8` (`fonts.rs:734-749`), so an unquantised zoom sweep restarts glyph rasterisation mid-session. Whatever step is chosen states the budget it implies.

This does not reopen [ADR 0005](0005-defer-source-addressing-for-infinite-canvas.md). The Grid stays fixed and nothing here assumes an infinite Source. What it changes is reachability: a Grid drawn through a container that lays out every Cell cannot serve a sparse infinite canvas, and one drawn from a transform the console owns, over the Positions the viewport covers, can. Source addressing stays deferred exactly as ADR 0005 left it.
