# Time and feedback are explicit Tick inputs

Timing, ordering, and Bang-lifetime clauses below are superseded where they conflict with [ADR 0032](0032-schedule-tick-execution-by-dependency.md). The Sequence-broadcasting clause is superseded for Delay `~*` and Euclidean `~%` by [ADR 0039](0039-pulse-functions-refuse-a-sequence-operand.md), which refuses a Sequence at their operand positions because a widened pulse has no answer for an element that does not Bang; Clock `~.` broadcasts as written below. Other decisions remain in force.

Clock, Delay, and Euclidean Functions adapt Orca's established formulas using the current Tick as an interpretation input and Number operands. Clock produces a Number, while Delay and Euclidean produce a first-class Bang with the same-Tick delivery and display lifetime defined in [ADR 0032](0032-schedule-tick-execution-by-dependency.md). The first Playback Tick is absolute Tick `0`, and each subsequent Tick increments that unsigned counter by one. Clock `~. rate modulus` returns a Number equal to `floor(Tick / rate) % modulus`: rate is the number of Ticks per step, modulus is the number of steps, and their product is the complete cycle length. Delay `~* rate modulus` Bangs exactly when `Tick % (rate * modulus) == 0`, including Tick `0`. Thus modulus `01` Bangs once per `rate` Ticks rather than every Tick. A zero rate or modulus diagnoses, and the cycle product is calculated in a wider integer without byte wrapping.

Euclidean `~% hits steps` uses Orca's bucket distribution and phase. After validating positive `steps`, it first reduces the absolute Tick without addition, `tick_in_cycle = t % steps`, then calculates `phase = (tick_in_cycle + steps - 1) % steps`; it Bangs when `((hits * phase) % steps) + hits >= steps`. Reducing `t` before the phase offset makes the formula mathematically equivalent to `((hits * (t + steps - 1)) % steps) + hits >= steps` without overflowing the absolute Tick counter. The phase, multiplication, addition, and comparison are evaluated in a wider unsigned integer before any Number conversion. Validation checks zero steps first, then hits greater than steps; therefore `(hits, steps) = (00, 00)` diagnoses rather than applying the zero-hits rule. With positive steps, zero hits produces no Bangs and equal hits and steps Bangs every Tick. Euclidean's numeric operands follow ordinary Sequence broadcasting; each broadcast element applies the formula independently at the same Tick.

Increment `~+ step modulus` and Interpolation `~> rate target` read their previous visible Number through the ordinary result Portal in working Source at their turn, treating an empty Portal as the initial Number `00` and diagnosing any other present Language Unit. Increment returns a Number equal to `(previous + step) % modulus` and diagnoses a zero modulus. The addition and modulus are evaluated in a wider unsigned integer before converting the result to a Number, so byte overflow cannot occur before the modulus. Interpolation moves by at most `rate`: when below the target, it returns the target if `rate >= target - previous` and otherwise returns `previous + rate`; when above the target, it returns the target if `rate >= previous - target` and otherwise returns `previous - rate`; when equal, it returns the unchanged target. Each distance is calculated only in the branch whose ordering makes its subtraction non-negative, and the rate comparison clamps to the target before a step subtraction that would underflow. The remaining addition or subtraction is evaluated in a wider unsigned integer before converting to a Number. Rate `00` intentionally holds the current value.

Increment and Interpolation are scalar exceptions to pervasive Sequence broadcasting. Their explicit operands and prior visible result must each be one Number; a Note, Sequence operand, or prior Sequence diagnoses. This keeps their complete cross-Tick state visible as exactly one Atom rather than inventing implicit conversion, hidden element identity, resize, or stale-tail state.
