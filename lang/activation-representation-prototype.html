FOCUSED REPRESENTATION PROTOTYPE

Where should an Activation Character live?

Actual Orcvs syntax is shown throughout: Directional Bang Functions *^, *v, *<, and *> emit the Source-resident Activation Characters ^^, vv, <<, and >>. This prototype compares two implementation models without changing that language.

Guided evidence

Model A: spatial Language Unit

Hypothetical representation: LanguageUnitKind::Activation(Direction), scheduled from the Language Map.

Model B: source-encodable value

Hypothetical representation: Atom::Activation(Direction) in a standalone Expression, special-cased by Tick planning.

Reuse and duplication

Model A

Reuses Language Map recognition, anchors, Footprints, Grid navigation, root queries, Glyph derivation, diagnostics, ordered Source writes, and next-Snapshot rebuilding. It does not use Function evaluation, runtime values, or Sequence machinery.

Model B

Reuses runtime-value spelling, parser records, and token Glyph conversion. It still duplicates spatial scheduling, collision, root delivery, clear/write ordering, and generated-Source guards; it also needs exclusions from Function operands and pervasive Sequence extension.

Decision: choose Model A. The behavior is spatial, and its facts are already local behind the Language Map/Tick-planning interface. Activation Characters gain no ordinary Expression or Sequence capability.
