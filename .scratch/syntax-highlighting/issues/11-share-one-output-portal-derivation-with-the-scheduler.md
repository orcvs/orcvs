**2026-09-25 — resolved.** The shared derivation is per positioned entry, not per root, because the scheduler needs a width for every computation: a nested Function's width is what its parent widens over, and a replacement's width check re-applies the rule to a hypothetical Function. So:

- `ExpressionEntry::sequence_capability` (`orcvs/src/source/language_map.rs`) answers, per entry of `positioned()`, whether it may answer a Sequence. `LanguageMap::output_portal_reservations` reads the root's answer from it, and tick planning's `computations` sets every `Computation::reserved` from it. `derive_reservations` no longer runs in production.
- `may_answer_a_sequence` is ADR 0036's rule for one Function. The Language Map's pass applies it per entry; `reserved_for` (behind `Lookup::would_reserve`, used by the replacement width check) applies it to one computation over its settled children. `Lookup::new`'s debug assertion now checks the two agree.
- `Portal::reservation` is the width geometry both read: the Cell pair, or the rest of the row. `Reserved::cells_from` and `output_portal_reservation` both call it.
- `derive_reservations` survives as `#[cfg(test)]` only, for `stated::plan_with_answers` and its direct test: a fixture that states a `Reserved::Row` no declaration derives needs its ancestors widened over it, and the Language Map cannot know a stated width.
- The agreement module is reduced to the Source-writing exclusion `05` names (`mod output_portal_exclusion`, Advance and Emit). Every other root reserves the same Cells by construction: the same capability, the same `Portal::named` resolution of `output_portal()`, the same `Portal::reservation`. The general comparison and its property test are gone; `language_map.rs`'s `mod output_portal` keeps the per-case coverage tests.

No Tick test changed. `orcvs` has 634 passing tests with `PROPTEST_CASES=32`.

## Agent Brief

**Category:** enhancement
**Summary:** Tick scheduling reads its Output Portal Reservations from the Language Map's derivation, and the agreement test between the two derivations goes.

**Current behavior:**
The Language Map answers, per root, its Output Portal Reservation range and whether it is Sequence-capable. The Output Portal highlight reads that answer. Tick scheduling derives its own scalar and Sequence-capable reservations bottom-up over tick planning's `Computation` tree. A test-only flattening of the Language Map's answer is compared against the scheduler's reservations to prove the two agree.

**Desired behavior:**
One derivation owns which Cells each root's Output Portal reserves, including the bottom-up widening a nested Function contributes. Tick scheduling and the highlight both read it. If the scheduler cannot read it (for example because a reservation depends on something only tick planning knows), the reason is recorded where the two derivations meet and the agreement test is kept, reduced to what the Language Map cannot know.

**Key interfaces:**
- The Language Map's per-root Output Portal Reservation list (range plus Sequence-capability): becomes the single answer, or gains what the scheduler's widening needs.
- Tick scheduling's reservation derivation over `Computation`: stops deriving its own reservations and reads the Language Map's.
- The test-only Output Portal Cell flattening and the agreement test built on it: removed, or reduced to the exclusions `05` names.

**Acceptance criteria:**
- [x] Tick scheduling reads its scalar and Sequence-capable reservations from the same derivation the Language Map carries, or the reason it cannot is recorded.
- [x] The agreement test is removed, or reduced to the exclusions `05` names.
- [x] No schedule changes: every existing Tick test passes unchanged.
- [x] `cargo clippy --package orcvs --all-targets --locked -- -D warnings`, `cargo nextest run --package orcvs --locked` and `--package console` pass.

**Out of scope:**
- The fitted Output Portal highlight rule and its blank-Cell defect (`syntax-highlighting/14`).
- Keeping a Tick's answer span (`13`, rejected; see `.out-of-scope/keeping-a-ticks-answer-span.md`).
- Any change to which Cells a Reservation covers.
