# 24 — Reduce lang's per-Tick work and allocations

**What to build:** Interpreting a Tick's Turns does only the work the answers need. The shipped path is `Interpreter::execute_function`, called once per Turn by `orcvs`: it builds a `Context` sized `operands.len() + 1` and clones every operand `Value` onto it, so a Sequence operand is cloned as well. Reverse, Concatenate and Replace rebuild through `Sequence::new`, which re-checks membership of values that are already valid members, and note conversion checks its range twice. The operand stack's own allocation is allocation-reduction/03; this ticket covers the rest of the path.

Random's per-element generator is out of scope: ADR 0013 requires a fresh 32-byte ChaCha seed per scalar result, pinned by `random_golden_vectors_pin_the_adr_seed_chacha8_word_and_range_mapping`, and `ChaCha8Rng` lives on the stack, so it costs CPU, not allocation. Changing it means superseding the ADR first.

**Blocked by:** 05 — Diagnose silent drops in lang; 09 — Move lang test-only API behind cfg(test).

**Status:** resolved

- [x] A Sequence operand's members are not cloned anywhere on the binding path, or each remaining clone is measured and kept with the measurement recorded here. The path clones up to three times today: `orcvs` copies each child result into the Turn's operands (`source/tick/execution.rs`), `Interpreter::execute_function` pushes a clone of every operand, and the whole-value binds `bind_sequence_required` and `bind_sequence_operand` (`lang/src/stack.rs`) clone again.
- [x] Reverse and Concatenate build their Sequence without re-checking membership; Replace checks only the replacement.
- [x] Note conversion checks its range once.
- [x] The allocation tests measure `execute_function`, the path `orcvs` calls, not `execute`, and are updated to the new, lower ceilings; a benchmark over `execute_function` shows the reduction. allocation-reduction/03 adds that test and benchmark; if this ticket lands first, it adds them and 03 reuses them.
- [x] Every `#[inline(always)]` is kept only where a benchmark justifies it; the rest become `#[inline]` or are removed, with the measurement recorded in this ticket. lang-foundations/02 and 07 recorded the benchmarks that kept the current attributes; they are the baseline.
- [x] Interpreter property tests pass unchanged.

## Comments

**2026-09-25 — audited against `origin/main` `199c3331`.** `lang/` is unchanged since the baseline. Corrected: the shipped path is `execute_function` per Turn, not a fresh stack per Expression through `execute`, and the allocation test measured the latter. The operand-stack criterion duplicated allocation-reduction/03 and moved there. The per-call Random criterion contradicted ADR 0013 and is out of scope. Membership re-checks are CPU work, so the ticket now speaks of work as well as allocation.

**2026-09-25 — binding path widened.** Criterion 1 named only the push onto the stack; the whole-value binds clone a Sequence again, and `orcvs` clones it before `lang` sees it. Ownership of the `execute_function` allocation test and benchmark is settled with allocation-reduction/03.

**2026-09-26 — implementation (epic PR 13).** Implemented in orcvs/orcvs#159 on branch `lang/reduce-allocations`, stacked on #156 (epic PR 11).

- *Binding path.* `Interpreter::execute_function` takes its operands by value (`IntoIterator<Item = Value>` with an exact, double-ended iterator) and moves each onto the Operand Stack. `ValueOperands::from_values` takes the popped operands by value, so `bind_sequence_required` and `bind_sequence_operand` move the Sequence into its role. In `orcvs`, a Turn takes a surviving child's answer out of its state (`Option::take`) instead of cloning it — a child's one consumer is its parent's Turn — and `deliver_value` stores the answer after projecting it by reference, so the store is a move. An answer with no Output Portal to write is no longer rendered: every projection arm plans or diagnoses a write at one, so skipping it is behaviour-preserving, and it was the remaining length-dependent cost of nesting a Sequence. No Sequence member copy remains between a child's answer and the Function body; the only per-member allocations left are answers that are new Sequences (a broadcast result, a concatenation, a Range).
- *Membership.* `Sequence::reversed`, `concatenated` and `replaced` (crate-private) derive a Sequence from Sequences in place. Reverse and Concatenate check nothing; Replace checks only the replacement, after the empty-Sequence refusal as before.
- *Note conversion.* `.^` over a Number defers to `Note::try_from`, which is the one range check and already answers `NoteConversion`.
- *Allocation evidence.* `lang/tests/allocation.rs` measures `execute_function`. The call fixture test from #156 hands each call its operands by value through inline storage, so its figures are unchanged: 8 blocks / 408 bytes, one Operand Stack block per call, which allocation-reduction/03 owns. New tests pin one Turn at a time (blocks/bytes, before → after, measured stacked on #156 when the Operand Stack held a slot for the answer):

  | Turn | 16 members | 64 members |
  |---|---|---|
  | `.+` over Atoms | 1 / 72 → 1 / 72 | — |
  | Reverse | 4 / 432 → 1 / 48 | 4 / 1584 → 1 / 48 |
  | Replace | 4 / 480 → 1 / 96 | 4 / 1632 → 1 / 96 |
  | Select | 3 / 328 → 1 / 72 | 3 / 1096 → 1 / 72 |
  | Subtract (broadcast) | 3 / 328 → 2 / 200 | 3 / 1096 → 2 / 584 |
  | Concatenate | 7 / 968 → 2 / 328 | 7 / 3656 → 2 / 1096 |

  After the change every remaining block is the Operand Stack or the answer itself. On `main`, where #156 sizes the Operand Stack at the operand count, each figure is one `Value` (24 bytes) smaller: `.+` 1 / 48, Reverse 1 / 24, Concatenate 2 / 304. `orcvs/tests/allocation.rs` adds `nesting_a_sequence_answer_costs_the_same_whatever_its_length`: the cost a nested Reverse adds to a Tick (`:<:-00NN` minus `:-00NN`) is measured at 16 and 64 members and asserted equal. Before: 13 blocks / 697 bytes against 17 / 2233. After: 3 / 177 at both lengths — the Reverse Turn's Operand Stack, its `Tokens` signature `Vec` in `opens_turn`, and its operand `Vec` in `operands`. Those two `orcvs` per-Turn blocks hold no Sequence member and are outside this ticket; they are recorded here for whoever next takes the Turn path.
- *Benchmark.* `lang/benches/lang.rs` adds the `execute_function_operands` group, beside #156's floor-guarded scalar `execute_function`: one Turn each for Add, ConvertToNote, Reverse, Replace, Concatenate and Subtract over 64-member Sequences, operands built outside the timed routine. Local, Apple Silicon, `cargo bench --package lang --locked --bench lang -- '^execute' --noplot --warm-up-time 1 --measurement-time 3`, three to four runs each interleaved, best-of shown (ns): `execute` 63 → 61; Add 46 → 45; ConvertToNote 41 → 41; Reverse 190 → 56; Replace 184 → 42; Concatenate 365 → 142; Subtract 390 → 376. The ratio gate and floors run only on pull requests into `main`, so the CI comparison happens when this branch's base becomes `main`.
- *`#[inline(always)]`, scoped to the touched paths.* Relaxing every attribute in `stack.rs`, `sequence.rs`, `interpreter.rs`, `functions/sequence.rs` and `functions/numeric_conversion.rs` to `#[inline]` (keeping `Stack::broadcast`, whose own measurement is in its doc comment) left every Turn flat except Subtract, 376 → 454–471 ns. Restoring `stack.rs` alone left Subtract at 422–428 ns; restoring `sequence.rs` as well returned it to 373–374 ns. So the attributes in `stack.rs` and `sequence.rs` are kept as measured, and the eleven in `interpreter.rs` (`execute`), `functions/sequence.rs` and `functions/numeric_conversion.rs` become `#[inline]`, measured flat (`execute` 60–62, ConvertToNote 39, Reverse 56, Replace 42, Concatenate 142 ns). Per-attribute bisection inside `stack.rs` and `sequence.rs`, and the attributes in files this change does not touch, are split into lang-foundations/12.
- *Atom alignment (#156), for the maintainer's decision.* This change does not alter `Atom`. As a probe only, the `execute` and `execute_function` benches were rerun with `#[repr(align(8))]` removed (a four-byte Atom), same command, three runs under a loaded machine, typical value (ns, eight-byte → four-byte): `execute` 61 → 69–71; Add 45 → 46; ConvertToNote 41 → 40; Reverse 56 → 58; Replace 42 → 50; Concatenate 142 → 98; Subtract 376 → 378. The four-byte Atom costs the scalar and in-place paths a few nanoseconds and halves every Sequence's bytes, which is what Concatenate's answer allocation and copy measure. On the shipped path neither width is uniformly faster; the attribute's `execute` rationale holds, and a Sequence-heavy Source would favour removing it. Moot on `main`: #156 removed the attribute before this merged, and removed `execute` with its benchmark, so the `execute` figures in this note have no benchmark to reproduce them.
- *Commands.* `cargo fmt --all -- --check`; `cargo clippy --package lang|orcvs --all-targets --locked -- -D warnings`; `PROPTEST_CASES=32 cargo nextest run --package lang|orcvs --locked` (285 and 663 passed), and the workspace gates. Interpreter property tests pass unchanged.
