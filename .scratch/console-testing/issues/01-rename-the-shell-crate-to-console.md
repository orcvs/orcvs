## Comments

The glossary already speaks this way. `CONTEXT.md` uses "console" as a plain noun inside the
definitions of Orcvs, Cursor, Marker, and Render Frame, and defines it nowhere. Meanwhile
Application Command Function lists "shell command" under `_Avoid_`, so the crate is named after a
word the glossary warns off.

Do this before the test work rather than after. The tests added by `03`, `04` and `05` bake crate
paths into new files, and renaming afterwards means a second sweep across them.

`feat/egui-theming` is not the source of this rename and is not a prerequisite. That branch is an
ancestor of the current code, not a pending redesign: its `console/src/` still holds `app.rs`,
`grid.rs`, `playback.rs` and `render_frame.rs`, from before `crate-boundaries` extracted the `orcvs`
crate, and its merge base with `main` is from 2024-11-12.

### Resolution (2026-09-11)

`git mv shell console` carried the whole crate, history included. `[package] name`, `[lib] name`
and `[[bin]] name` are `console`; both `path` fields are crate-relative and did not move. The
workspace `members` list names `console`, and `Cargo.lock` was regenerated by cargo rather than
hand-edited.

The sweep reached further than the checklist named, because more than the checklist cites the crate:

- `console/assets/sw.js` caches `./console.js` and `./console_bg.wasm`. Those are trunk's output
  names, derived from the bin name, so they had to follow the rename or the service worker would
  cache-miss every artifact. `mise run check_wasm` builds `console/dist/console.js` and
  `console/dist/console_bg.wasm`, which is what confirms the pair still match. The cache name goes to
  `orcvs-pwa-v3` in the same edit: a browser holding the v2 cache holds `shell.js` and
  `shell_bg.wasm` entries that no build writes again, and evicting a cache whose artifact set has
  changed is what `pre-split-defects/06` versioned the name for.
- `scripts/tests/check-tooling-contract.sh` inverts three fixtures. Each one used to mutate a live
  `shell` spelling into a `console` one to prove the contract rejects it; with the rename those
  mutations are no-ops, so each now mutates the live `console` spelling into the retired `shell`
  one. `test_console_debug_package_is_rejected` is `test_shell_debug_package_is_rejected` for the
  same reason: the retired package name in `.vscode/launch.json` is now `shell`.
- `.github/workflows/tooling.yml` path-filters `console/Cargo.toml`, `console/Trunk.toml` and
  `console/assets/sw.js`, because `scripts/check-tooling-contract.sh` derives that filter from the
  paths the fixture suite reads and fails when the two sets diverge.
- `.github/workflows/test.yml` needed no configuration change, as this issue expected. One prose
  comment in it named the crate and now names `console`.
- `docs/tooling.md`, `AGENTS.md`, `docs/research/memory-testing-in-ci.md`, `.vscode/launch.json`,
  and doc comments in `lang`, `orcvs` and `console` that named the crate or cited its paths.

`mise run check` was not run. `CLAUDE.md` defers it to CI, along with `check_merge` and `test_wasm`,
and that instruction outranks this checklist; the last box stays unticked rather than being claimed
on a command nobody ran. What ran locally instead: `cargo fmt --all -- --check`, crate-scoped clippy
and `cargo nextest run` for `console`, `orcvs` and `lang`, `bash scripts/check-tooling-contract.sh`
and its fixture suite, `actionlint`, `zizmor --offline .github/workflows`, the roadmap suite,
`mise run audit_deps`, and `mise run check_wasm` for the trunk output names above.

ADRs 0022 and 0037 still name `shell` and cite `shell/src/diagnostics.rs`. They are dated records of
decisions taken when that was the crate's name, so they are left as written. Resolved issues under
`.scratch/` are left for the same reason; open ones that cite paths a reader would follow were
updated.
