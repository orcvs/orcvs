# 01 — Decide where Source colour authority lives

**What to decide:** Whether the ten Source Paint roles are viewer settings that storage owns, or theme tokens that a scheme owns, and record the answer as an ADR. Every other issue in this effort inherits the answer.

**Blocked by:** None — can start immediately.

**Status:** ready-for-human

**Tags:** release/v1

## The answer

`docs/adr/0050-a-theme-maps-facts-to-channels.md`, status `proposed`. It is written and needs acceptance, not authoring. In short:

A Cell carries independent facts — the parser's claim, whether the slot is written, whether the Cell is in an Output Portal Reservation, whether it is selected. The console draws them through independent channels — glyph colour, fill, border, overlays. A theme is the mapping between the two and nothing else decides it. Today `style.rs::operand_paint` hardcodes that mapping as control flow, which no theme can restate.

Two namespaces follow from the split. Tokens are spellings and take **base16** slots, assigned by the semantic roles base16's styling guidelines state, so every published scheme drops in. Diagnostic, Output Portal, Fill tint, Region, selection and the Cursor are affordances and take **named keys**, the way `editorError.foreground` does. Diagnostic therefore never competes with Sequence for `base08`.

Storage holds a scheme name or its sixteen values plus per-role overrides keyed by scheme. Never a resolved colour, which is the property `SourcePaintSettings` lacks.

## Comments

**2026-09-20 — opened from triage of `05`.**

> *This was generated by AI during triage.*

`05` could not be triaged on its own terms: it presupposed that persisted `SourcePaintSettings` is the right source of truth for chrome, which is the question here.

**2026-09-20 — the decision was taken and the ADR written.**

Reached by working from how the problem is already solved elsewhere rather than from the shipped code. The route mattered: an earlier draft of this issue framed the choice as "overrides over a theme-selected palette" versus "theme tokens, no editor", and both were wrong in the same way — each still folded the Source Tokens into egui's dark/light `Visuals` model, which `03` had already argued against in an acceptance line nobody had read back: glyph colour is a language concept, so the toolkit's theme model cannot define it.

Three corrections shaped the ADR. Syntax and chrome are separate namespaces, as VS Code's `tokenColors` and `colors` are. Base16 is the syntax format, because a format no published scheme targets cannot accept Solarized or Gruvbox, and ecosystem schemes are the whole reason to have a format. And a Diagnostic is an affordance, not a spelling — VS Code themes squigglies through `editorError.foreground` in the workbench namespace, never through a token colour — which is what frees `base08` for Sequence.

One claim made along the way was wrong and is worth recording so it is not repeated: base16's styling guidelines assign **semantic roles only** and never name colours. "base08 is red" is convention among scheme authors and template repos, not spec.
